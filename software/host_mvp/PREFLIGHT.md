# 实验前启动自检（host v0.9 / firmware v0.4）

此命令独立于采集界面运行。先完成接线、预热、称重标定及实际安全链检查，停止执行器，并关闭占用同一串口或相机的程序。打开串口可能因板卡的DTR/RTS电路触发复位；检查过程中不要让滚筒运行。

在 `software/host_mvp` 目录、已安装 requirements 的 Python 环境中运行：

```powershell
python preflight.py --port COM5 --camera-index 0
```

`COM5` 仅为示例，须替换成已确认设备端口。默认观察12秒，要求至少5帧、至少4秒主机接收跨度、连续序号、MCU时间递增及相邻帧间隔不超过3秒，结束时遥测也须保持新鲜。可用 `--seconds 30` 延长，允许5～120秒。

默认启用掩码为7（三路TGS，第四通道空值）。更改硬件配置时须同步指定 `--expected-mask`，不能仅为让自检通过而更改预期。固件 `info` 新增设备身份、掩码及已配置I²C器件的应答结果；仅探测指定地址，不遍历总线、不执行原 `scan` 命令。未收到配置时，在首条传感帧后最多再查一次 `info`。不会发送去皮、标定、泵阀或电机命令。

## 检查内容与结果

| 检查 | 通过依据 |
|---|---|
| transport | 观察窗口完整，无串口错误、乱码、残缺行或结束时断流 |
| identity | info与窗口全部帧的设备ID、固件、硬件、来源一致；实际运行要求hardware来源 |
| i2c | ADS气敏、环境SHT、腔内SHT、MLX、BME及固件上报的其他已配置器件全部应答 |
| channels | info与全部帧的启用掩码符合预期 |
| calibration | 已保存有效称重比例/零点，窗口内参数一致，当前称重在0～20000g范围 |
| continuity | 满足帧数、接收跨度、序号和时间连续性要求 |
| sensor_readiness | 全部帧质量OK、核心测量值有限、启用通道有值且禁用通道为空；WARMUP不通过 |
| outputs_off | 全窗口泵阀及滚筒运行命令为关闭；启用滚筒时还要求反馈小于1RPM、PWM为0且无锁存故障 |
| camera | 隔离子进程成功采集和编码一帧，8秒超时后结束子进程 |
| disk | 实际批次目录可写并完成小文件fsync，剩余空间达到配置阈值 |

`overall=pass` 对应退出码0；失败或未知对应退出码2。`--skip-camera` 会把相机标为未知，总体不会通过；旧固件不支持完整I²C信息时也不会获得完整通过。缺少物理执行器反馈的旧协议不会被推断为关闭。

## 相机和磁盘参数

可用 `--exposure`、`--white-balance` 传入相机驱动支持的固定参数，需与采集界面“相机参数”的设置一致。未传入时仅验证能拍照，不证明固定曝光/白平衡。驱动设置、读回、图片字节数和SHA256写入报告，照片不保存。固定光照、色卡和真实画面一致性仍需人工验收。

磁盘检查默认针对仓库 `data/raw`。如实际批次存放位置不同，指定 `--data-root`；报告目录由 `--output` 独立指定，默认 `data/preflight`。`--minimum-free-gib` 默认为2，仅为启动阈值，须按实验时长和图像大小留足空间。小文件测试不证明持续写入吞吐或8小时容量足够。

## 记录、批次衔接与边界

每次创建独立时间戳/随机后缀目录，保留 `raw_serial.jsonl` 和 `report.json`，不覆盖历史报告。原始接收字节以Base64保存，包括无效UTF-8；报告包含原始日志SHA256、配置应答、窗口帧、主机时间及每项检查证据。检查失败仍生成报告；程序中断或保存失败留下 `INCOMPLETE`，不能当成完整报告。

自检退出释放串口和相机后，再打开采集界面。把报告目录写入该批次档案的“标定方法、结果与记录位置”字段，并随原始批次数据一起备份；`data/preflight` 不提交Git。当前界面不会自动导入报告或把历史报告当成启动许可，重新接线、改配置、换设备或重启后需重新检查。自检与实际批次间的状态变化应靠采集诊断继续监控。

`outputs_off` 仅证明观察窗口内的软件命令和可用编码器读数，不证明上电瞬态、继电器物理触点、阀位或独立急停。通过也不证明测量精度、滚筒实际负载或长期稳定性。报告统一保留 `hardware_verified=false`，实物验收单需另行签认。
