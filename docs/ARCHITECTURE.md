# 系统架构与接口边界

## 范围

研究对象为凤凰单丛做青的**摇青、静置以及两者之间的状态观测**。目标并非替代整条制茶生产线，而是为不同工艺条件下的多模态数据采集和后续闭环研究提供可复用实验平台。

## 逻辑结构

~~~text
[TGS / BME688 气敏]   [SHT31 环境/腔体]  [MLX90614 叶温]  [HX711 质量]
           \               |              |                /
                  [ESP32-S3：传感器采集、诊断和质量标记]
                                   |
                      USB CDC / JSON Lines
                                   |
                 [PySide6 上位机：批次与人工事件]
                    |           |             |
                 原始存储      相机/标签      设备命令审计
                    |           |             |
                    +-----------+-------------+
                                |
                 [回放、窗口工程分析、完整性检查]
                                |
         [未来：经验证的状态估计与影子工艺建议]
                                |
          [未来：人工批准 + 受安全约束的执行]
                                |
                 [未来：跨批次 A/B/C 品质评价]
~~~

虚线含义以“未来”文字表示：默认分支并未完成所有模块间的自动闭环接口。离线模型预研处于独立 PR，不意味着生产界面已接入。

## 目录职责

| 目录 | 职责 | 公开边界 |
| --- | --- | --- |
| `hardware/esp32_s3_mvp` | ESP32-S3 平台与传感器驱动、可选控制逻辑 | 固件代码、模拟与编译 ≠ 物理验收 |
| `hardware/PINOUT.md`、`MOTOR_BASELINE.md` | 电气接口约束及电机安全设计基准 | 接线实际完成情况需现场核查 |
| `software/host_mvp` | 连接、采集、批次管理、相机、人工标注、回放 | 上位机工作流 ≠ 制茶状态识别能力 |
| `scripts/` | 工作簿数据一致性与指标复核 | 复算 ≠ 原始测量真实性认证 |
| `data/hardware_tests/` | 处理结果与已知限制 | 不等同公开所有原始批次 |

## 关键数据约定

固件按 JSONL 发送数据；传感数据可能因缺设备、预热、未标定、通信问题而为 `null` 或带 `quality_flag`。不可用上一次的数值静默代替失败读数。上位机补充时间来源、人工标签、命令审计、批次元信息和原始串口证据。气体信号及质量变化不能直接等同茶叶化学成分浓度、叶含水率或做青成熟度。

详细数据协议及其版本约束请优先以[固件 README](../hardware/esp32_s3_mvp/README.md)与[上位机 README](../software/host_mvp/README.md)中的实际实现为准。

## 安全设计界限

运行中的电机、阀、泵必须具有与 PC GUI 和软件命令**独立**的物理安全措施。串口、GUI、网络或 MCU 状态反馈均不能取代急停和断电隔离。项目目前不是商业设备，也没有安全认证。
