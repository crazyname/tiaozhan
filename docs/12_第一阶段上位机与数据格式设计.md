# 青韵智控第一阶段上位机与数据格式设计

本文件用于统一第一阶段的数据采集软件、串口协议、文件结构和实验事件标记。

目标不是先做“漂亮大屏”，而是建立一个**稳定、可追溯、可重复、方便后续建模**的数据基础设施。

核心原则：

> **原始数据永远保留，处理结果可以重算；所有传感器共享同一时间轴；所有人工操作必须留下事件标记。**

---

# 1. 第一阶段软件边界

上位机只负责：

1. 设备连接；
2. 实时数据显示；
3. 原始数据落盘；
4. 实验事件标记；
5. 相机图像采集；
6. 实验元数据记录；
7. 基础报警；
8. 实验结束后的完整性检查。

第一阶段**不负责自动做青控制**。

不要把时间投入到：

- 复杂账号系统；
- 云平台；
- 手机 App；
- 3D 动画；
- 花哨仪表盘；
- 未验证的 AI 实时预测。

---

# 2. 推荐软件技术栈

推荐：**Python 桌面上位机**。

## 2.1 第一选择

- Python 3.12；
- PySide6：桌面 UI；
- pyqtgraph：实时曲线；
- pyserial：串口；
- OpenCV：UVC 相机；
- pandas / numpy：基础处理；
- SQLite：实验索引和元数据；
- CSV：第一阶段原始时序数据；
- YAML / JSON：配置文件和批次元数据。

选择 PySide6 而不是网页式上位机的主要原因：

- Windows 下串口和摄像头控制更直接；
- 不依赖浏览器；
- 适合长时间本地运行；
- 后续可直接打包成可执行程序。

# 3. 系统模块划分

```text
serial_reader      读取 MCU 数据
camera_worker      相机定时采图
data_buffer        内存缓存
logger             CSV / JSON / SQLite 落盘
event_manager      摇青、师傅判断等事件标记
plot_manager       实时曲线
health_monitor     掉线、越界、缺包检查
session_manager    批次 / 实验生命周期
config_manager     采样率、端口、通道配置
```

原则：采集、显示、存储分离。

即使 UI 卡顿，也不能导致原始数据丢失。

---

# 4. MCU → 上位机通信协议

第一阶段使用：

> **USB / 串口 + JSON Lines**

即 MCU 每发送一帧，就发送一行 JSON，以换行符结束。

优点：

- 人能直接读；
- 调试方便；
- Python 解析简单；
- 后续升级二进制协议时仍能保留字段定义。

---

# 5. 传感器数据帧

示例：

```json
{
  "type": "sensor",
  "seq": 10231,
  "t_ms": 1849234,
  "gas_adc": [15230, 19331, 14002, 22410],
  "gas_v": [1.21, 1.54, 1.11, 1.78],
  "bme688_gas_ohm": 183240,
  "chamber_t_c": 27.42,
  "chamber_rh_pct": 71.30,
  "ambient_t_c": 26.95,
  "ambient_rh_pct": 69.84,
  "leaf_t_c": 26.63,
  "mass_g": 3824.6,
  "pump": 1,
  "valve_sample": 1,
  "valve_purge": 0
}
```

## 必须保留的两个时间

### MCU 时间

`t_ms`

用于判断设备内部采样是否连续。

### 上位机时间

上位机收到数据后额外加入：

- `host_time_iso`；
- `host_monotonic_s`。

用途：

- 与图片 / 人工事件对齐；
- 处理电脑系统时间变化；
- 发现串口阻塞。

# 6. 采样频率建议

## MCU 内部采样

| 数据 | 建议内部频率 |
|---|---:|
| MOS / ADC | 5–10 Hz |
| 温湿度 | 1–2 Hz |
| 叶温 | 1–2 Hz |
| 称重 | 5–10 Hz |

## 上位机正式记录

第一阶段建议统一形成 **1 Hz 主时间轴**。

MCU 高频数据先做：

- 中值滤波；
- 均值；
- 标准差；

然后每秒输出一次汇总。

同时保留调试模式，可保存更高频 raw 数据。

## 图像

建议：

- 常规：每 30 s 1 张；
- 摇青前后：提高至每 5–10 s 1 张；
- 师傅关键判断时：立即手动保存一张高质量图。

第一阶段不需要录制全程高码率视频替代结构化图像采样。

# 9. 师傅判断标签设计

师傅判断不要只记录一句自然语言。

建议同时记录结构化字段：

```text
stage_label
aroma_level
leaf_softness
red_edge_level
water_loss_feeling
next_action
confidence
free_note
```

例如：

```yaml
stage_label: rest_after_shake_2
aroma_level: 4
leaf_softness: 3
red_edge_level: 2
water_loss_feeling: 3
next_action: continue_rest
confidence: 4
free_note: 花香开始明显，叶缘微红，暂不摇
```

其中 1–5 分量表必须在正式采样前定义清楚，不能实验后再随意解释。

# 15. 上位机 UI 第一版

第一版只需要六个区域。

## A. 批次信息

显示：

- batch_id；
- 原料；
- 操作员；
- 开始时间；
- 当前运行时间。

## B. 设备状态

显示：

- MCU；
- 串口；
- 相机；
- 气泵；
- 阀；
- 文件写入。

只用：

- 正常；
- 警告；
- 故障。

## C. 气味实时曲线

显示：

- 4–6 个 MOS / gas 通道；
- 可切换 raw / normalized。

## D. 鲜叶状态

显示：

- 质量；
- 相对失水率；
- 叶温；
- 温湿度。

## E. 图像预览

显示最新一张采样图。

## F. 事件按钮

至少：

- 摇青开始；
- 摇青结束；
- 师傅检查；
- 取样；
- 自定义备注。

# 16. 实时图不要过度处理

第一版曲线同时显示：

- raw；
- 简单平滑；
- 基线归一化。

不要只显示“漂亮的归一化曲线”而丢失原始信号。

MOS 可以初步计算：

```text
ΔV = V(t) - V0
ratio = V(t) / V0
```

如果后续换算传感器电阻，则保留：

```text
Rs
Rs/R0
```

但必须明确电路和定义，避免不同批次计算方式变化。

---

# 17. 相对失水率

统一定义：

```text
water_loss_ratio = (m0 - mt) / m0
```

其中：

- `m0`：该批次 T0 初始质量；
- `mt`：当前质量。

不要把不同批次的绝对质量直接作为主要比较指标。

---

# 18. 数据完整性检查

每次结束后软件自动生成 `session_check.txt`。

至少检查：

- 是否存在 meta.yaml；
- sensor 文件是否为空；
- seq 是否连续；
- MCU 时间是否倒退；
- 是否存在长时间缺包；
- 是否有 NaN / 越界；
- 图片数量；
- events 是否存在；
- SESSION_START / SESSION_END 是否成对；
- 存储空间是否异常。

---

# 19. 建议报警规则

第一版只做设备报警，不做“茶叶状态 AI 报警”。

例如：

- 3 s 未收到 MCU 数据；
- 相机连续 3 次采图失败；
- 质量读数突变超过阈值；
- 某气敏 ADC 长时间满量程；
- 温湿度传感器返回错误；
- 文件无法写入；
- 磁盘空间不足。

# 21. 版本管理规则

## 硬件版本

```text
HW-v0.1
HW-v0.2
```

## 固件版本

用 Git commit SHA。

## 上位机版本

用 Git commit SHA + 可读版本号：

```text
HOST-v0.1.0
```

## SOP 版本

```text
SOP-v0.1
```

任何影响数据含义的字段、采样率、气路时序发生变化，都必须升级版本。

# 23. 上位机第一阶段验收标准

进入第一批真实做青前必须满足：

1. 连续运行 ≥8 h 不崩溃；
2. 数据文件持续写入；
3. 串口掉线后能明确报警；
4. seq 缺包能被识别；
5. 图片和传感器时间可对齐；
6. 人工事件可一键标记；
7. 每批数据具有完整 meta；
8. 结束后自动输出数据完整性报告；
9. 任一原始数据都可以追溯到硬件 / 固件 / 软件版本。

---

# 24. 后续升级边界

完成多批次数据后，才进入：

- 实时特征提取；
- PCA / PLS / RF / XGBoost；
- 状态指数；
- 置信度；
- 工艺建议；
- 人工确认半自动控制。

在第一批数据之前不要先写死“最佳状态算法”。

---

# 25. 最终原则

上位机第一阶段的价值不是视觉展示，而是建立一个可信数据链：

> **什么时候测的 → 测了什么 → 设备是否正常 → 当时发生了什么工艺动作 → 师傅怎么判断 → 后续品质如何。**

只要这条链可靠，后面的算法、论文、专利、PPT 和挑战杯答辩才有真实基础。
