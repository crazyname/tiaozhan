# 青韵智控｜硬件测试后完整研发路线与验收标准

版本：规划 v1.0  
日期：2026-10-08  
适用项目：青韵智控——凤凰单丛做青多模态感知与自适应控制系统  
文档性质：**研发执行依据**，不是已经取得的技术成果或自动化效果声明。

## 0. 总目标、边界与执行原则

项目的最终可验证目标为：**利用真实鲜叶多源观测，在安全约束下给出合理的摇青/静置工艺建议，并检验其相对于固定程序是否改善成茶品质或降低批次间波动。**

技术主线固定为：

~~~text
基础感知与设备安全验收
  → 完整真实做青被动采集
  → 可复算的特征工程与人工标注
  → 跨批次做青状态估计
  → 人工确认的工艺建议
  → 受限半自动控制
  → A/B/C 品质对照验证
  → 达标后研究闭环自适应控制及现场试用
~~~

五条硬约束：

1. 优先复用现有固件和 PySide6 上位机，不重新建设已有采集、批次管理、相机、回放和工程分析功能。
2. 模拟、编译与单元测试只能证明对应软件行为；不能替代实物电气安全、传感器标定、真实做青或品质验证。
3. 所有模型结论按**独立做青批次**检验；同批次不同秒的数据不能分别进入训练集与测试集。
4. 任何工艺建议在安全链、真实设备和人工确认机制验收前**不得直接驱动滚筒**；低置信度、失联、传感器异常时保持安全停机或已验证的人工/固定工艺。
5. 不把“自动摇青”“电子鼻识别阶段”“使用 AI”单独宣传为原创突破。创新性必须由多模态增益、跨批次性能、决策可用性与成茶品质效果的对照实验支撑。

## 1. 研发基线与证据口径

### 1.1 已有基础

截至本文编制，仓库已有：

- ESP32-S3 N8R8 固件基线 QY-FW-0.4.0，GPIO、电气接口及模拟/真实构建约束见 [引脚规范](../hardware/PINOUT.md)、[固件说明](../hardware/esp32_s3_mvp/README.md)与[固件验证记录](../hardware/esp32_s3_mvp/VALIDATION.md)。
- PySide6 上位机 host v0.9.0：串口采集、批次元数据、原始帧与事件存储、人工标签、拍照索引、历史回放、工程分析、设备操作、故障日志和启动自检已有实现，见 [开发文档](../software/host_mvp/DEVELOPMENT.md)与[交接单](../software/host_mvp/HANDOFF.md)。
- 滚筒/电机的固件和上位机控制接口有软件实现；机械装配、编码器及独立安全链的实机验收必须另行确认，见 [DRUM-v0.1](../hardware/MOTOR_BASELINE.md)。
- 已提交作品材料报告：MOS 四个有效通道平均重复性 CV 6.18%、最大 CV 8.19%；SHT31 最大温度偏差 0.197℃、湿度偏差 1.506%RH；HX711 在 500–5000 g 标定的平均相对误差 0.162%；480 min 连续运行有效数据 28777/28800、完整率 99.92%；凤凰单丛**静置样品** 120 min 联合采集完整率 99.92%。数字及其限定条件见 [作品说明书](../submission/03_作品说明书/青韵智控_作品说明书主稿.md)。

**证据差异处理：** 2026-09-22 的固件交接单将实板、8小时验收列为未完成，而后续申报主稿报告了480分钟实物采集。应当以**实验日期、原始文件、设备ID、固件/上位机版本、操作者、协议、异常日志**逐项关联，更新相应验收记录。480分钟等于8小时，但不能未经核对就声称已经通过《HANDOFF.md》所要求的全部8小时联合验收项目。

现有120分钟试验是**静置样品联合采集**，不等于完整做青（多轮摇青—静置）或控制效果验证。

### 1.2 尚不能认定完成

- 完整真实做青流程、多独立批次与师傅状态标签的数据集。
- MOS 湿度干扰、气路清洗/残留、长时间漂移和不同茶批的稳健性检验。
- RGB 色卡/光照标定、独立叶温测量及所有宣称模态的真实接入验收。
- 状态识别、跨批次泛化、模型不确定性与决策效果。
- 电机及滚筒的实机安全验收、人工确认执行及自主控制效果。
- 与人工/固定程序的成茶品质对照、现场试用和产业化证据。

### 1.3 术语与测量边界

- **MOS 电子鼻**记录交叉敏感的相对气味响应指纹，不直接等于某种香气分子的浓度；四个“有效通道”应核查通道ID、传感器型号与BME688/模拟通道配置，不可默认为四个独立同型号MOS器件。
- **SHT31**用于所在测点的空气温湿度，不直接给出叶面温度。叶温需要已校准的独立测量。
- **相对质量损失**定义为 (m0 - mt) / m0，仅在一致的m0起点、容器处理和静置称重窗口下可比较；不可无条件称为绝对失水率或含水率。
- **软件发出命令 / 设备接受命令 / 确认机械动作完成**是三个不同事实；若缺少阀位、流量、转速或执行器反馈，不显示未经测量的“完成”。
- **模态缺失**应显式置空并记录原因；尚未接入视觉/叶温的试验不能标称全模态实验。

## 3. 研发阶段、开发任务与验收门槛

**原则：以验收门槛而非日历强行推进；下表时间为连续投入的粗略工期，真实茶季、合作方和实验条件可能延长。**

| 阶段 | 建议工期 | 交付物 | 进入下一阶段的硬门槛 |
|---|---|---|---|
| G0 实物基线复核 | 3–7天 | 设备/数据/标定验收单 | 真实与模拟来源、物理安全、时间轴可核验 |
| G1 长时采集与环境鲁棒性 | 1–2周 | 工程验收报告、湿度/清洗曲线 | 可靠采集并确定可用工况 |
| G2 完整做青与标注 | 依可获得批次持续进行 | 完整批次数据库、量表一致性结果 | 足够独立批次且标签可信 |
| G3 特征融合与状态识别 | 2–4周起 | 可复算基线模型、跨批次报告 | 优于预先规定的合理基线且校准可靠 |
| G4 工艺建议与人工确认 | 2–3周起 | 建议引擎、离线/在线审核记录 | 不执行危险建议，能解释、能拒绝 |
| G5 受限半自动执行 | 2–4周起 | 端到端安全联动和现场验收 | 独立急停/门盖/失联等安全测试通过 |
| G6 A/B/C 对照与品质验证 | 受原料和制茶周期约束 | 品质盲评、统计分析、失败记录 | 实证证明增益，或明确记录负结果 |
| G7 场景试用与成果材料 | 视合作条件 | 展示系统、BOM、试用与申报证据 | 所有对外说法均与原始证据一致 |

### 3.1 G0｜实物基线复核

任务编号 G0-01～G0-06：

1. **G0-01 资产/版本复核：** 拍摄实物、接线图、传感器型号与有效通道表；记录板卡型号、固件SHA、主机软件SHA、供电方式、标定版本与测点位置。核对四路气敏指标和真实固件通道映射。
2. **G0-02 证据挂接：** 将已有480 min、120 min、MOS/SHT31/HX711测试分别映射至原始数据、计算脚本、报告、标定器具和日期；缺失项显示“待核验”。
3. **G0-03 实板联调：** 启动、掉线重连、I²C地址、空设备null、ADC电压与质量标记按[固件验收表](../hardware/esp32_s3_mvp/VALIDATION.md)逐项填写。
4. **G0-04 称重再验收：** 验证静置稳定窗口、容器/托盘漂移、重复加载以及摇青时振动不可用样本的剔除策略。
5. **G0-05 设备安全：** 气泵/阀与滚筒分别验证启停/故障/掉电，禁止以UI按钮代替硬件急停和互锁。
6. **G0-06 基线冻结：** 形成“可继续试验设备基线单”，已通过、未通过、尚未测试分开列示。

**验收材料：** 设备基线表、标定证书/记录、实拍、原始日志、失败与整改表。未通过 G0 不得进行无人值守的动作试验。

### 3.2 G1｜采集可靠性、湿度与清洗恢复

优先补齐现有软件的**真实运行验收**，不重复实现已有SW-01～SW-07。

- **G1-01** 连续长时实机采集：分母定义为设备预期帧/主机收到帧/落盘帧，分别统计丢包、重启、队列溢出、磁盘异常、照片索引完整性；至少一次覆盖预定真实做青时长的测试。
- **G1-02** MOS 预热、洁净空气基线、短期/跨日重复性，记录响应峰、积分面积、恢复时长与CV。
- **G1-03** 湿度干扰：设计覆盖真实工况的多个湿度条件，固定气源与采样参数，比较补偿前后误差；不凭单次相关性证明补偿有效。
- **G1-04** 气路采样/吹扫：测试前轮残留、不同清洗时间、空气背景、气泵/阀故障；用残留阈值和恢复窗口决定实际采样节拍。
- **G1-05** 视觉与叶温（如已有物理接入）：固定光源/色卡、曝光/白平衡、相机位置及IR发射率、距离、视场；未接入则保留缺失字段和接口，不阻塞VOC+质量+环境的初期实验。
- **G1-06** 出具每批数据完整性、可用样本比例、无效时段和校准状态的机器可复算报告。

**验收：** 试验前明确可接受的包完整率、漂移上限、清洗残留与误差阈值；不事后根据结果修改标准。若不达标，先修复可靠性/测量链再进入建模。

### 3.3 G2｜完整真实做青过程与专家标注

- **G2-01** 按[做青采样SOP](10_第一批做青采样SOP.md)采集完整**摇青—静置循环**，记录原料来源、品种/香型、采摘日期和嫩度、投入质量、环境、设备及操作者。
- **G2-02** 全部动作记录目标值与实测值：摇青起止、转速、持续时间、人工干预、静置起止、取样/开盖、气路切换。
- **G2-03** 使用[人工标签量表](../software/host_mvp/LABEL_SCALE.md)记录阶段、香气、叶缘红变、柔软/回软状态、建议动作、记录人、时间与未知项。观察不自动写成事实。
- **G2-04** 多位专家对同一样本做盲评或独立评分，报告一致性；存在歧义时保留不同意见和修订链，不强行构造统一“真值”。
- **G2-05** 建立最少一批端到端走通作为流程验证；随后连续积累不同日期、初始状态和环境的**独立批次**。样本量须按可用批次和实际模型目标规划；单批数万个秒级点不等于数万个独立样本。
- **G2-06** 先做可视化与工艺相关性审查，检查气敏采样/清洗周期是否妨碍摇青决策的时间分辨率。

**验收：** 可从原始数据、照片、动作日志和人工标签重建至少一批真实完整做青；进入定量建模前必须有多独立批次和标签质量报告。无专业制茶资源时停留在数据平台与辅助监测，不虚构师傅标签。

### 3.4 G3｜可复算特征、多模态融合与状态识别

数据处理从简单、可解释的基线做起：

1. **质量控制：** 识别缺包、设备重启、通道故障、清洗/采样状态、异常值和振动称重区间。保留原始值及mask。
2. **时间对齐：** 区分MCU时间和主机收到时间，按事件窗口对齐；记录重采样方式和有效观察窗口，绝不伪造传感器的亚秒同步精度。
3. **特征提取：** VOC相对基线响应、斜率、面积及恢复特征；环境温湿度和趋势；相对质量损失/静置窗口速率；经校准的叶温与RGB颜色/纹理；前一次摇青后的时间及已知工艺历史。
4. **补偿试验：** 比较原始MOS、规则/线性湿度补偿与更复杂模型；使用独立湿度环境和批次验证是否真正提高稳定性。
5. **规则基线：** 专家阈值/时间规则作为第一基线，再用逻辑回归、随机森林、梯度提升模型作对照；只有数据量与任务性质支持时才尝试时间序列深度网络。
6. **独立批次验证：** 以batch_id分组做训练/验证/测试（或留批次/留日期验证），所有标准化、补偿拟合和特征筛选仅在训练划分学习；重复同一鲜叶样本/同日相关数据不得穿透测试边界。
7. **可解释与拒绝预测：** 输出阶段、趋势、概率/不确定性、关键特征和适用范围；报告低置信度样本占比、漏判率、混淆矩阵及校准误差。

**模型评估：** 宏平均F1、每阶段召回、跨批次性能下降幅度、置信度校准、推理延迟和失败案例。设定“仅时间/工艺历史”“单一VOC”“VOC+环境”“VOC+质量+环境”“全部实际可用模态”消融实验。没有统计意义的增益不写成多模态优势。

### 3.5 G4｜工艺决策与人工确认

首先实现**建议系统**，而不是直接自动驾驶滚筒：

- **G4-01** 输入当前可信状态、质量标志和已知工艺历史，输出“继续静置 / 建议检查 / 建议摇青 / 暂不建议”及推荐参数区间、置信度和依据。
- **G4-02** 通过专家制定的范围、最短静置间隔、最大转速/时长、禁止摇青工况与样品限制；推荐值必须落在合法、安全、设备支持的范围内。
- **G4-03** 设计拒绝建议：模态故障、信息过期、未验证茶样类型、过低置信度、模型不一致时返回“人工确认”，不填默认动作。
- **G4-04** 离线回放评估：使用历史批次回测建议时刻，但**不能**把离线拟合师傅历史动作当作提高成茶品质的证据。
- **G4-05** 在线影子模式（shadow mode）：系统生成建议，操作者按原工艺独立执行；记录建议/人工决策差异和处理结果，不让算法改变做青。
- **G4-06** 师傅确认版：人明确批准后允许向已验收的执行链提交受限命令；完整保留请求、批准人、实际反馈、撤销和超时日志。

**验收：** 状态未知、数据过期、传感器失效、拒绝/超时命令、回放数据异常都不能触发自动动作；人可以拒绝或改写建议并留下证据。

### 3.6 G5｜安全受限半自动与真正闭环

前提是[DRUM基线](../hardware/MOTOR_BASELINE.md)的独立安全链**实机验收**完成：

- 空载→模拟负载→真实小批量逐级试验实际转速/方向/计时/电流或驱动故障；确认编码器比例与停机响应。
- 独立硬件急停、门盖开关、安全继电器、主机失联、ESP32复位、断电恢复、超速和运动异常逐项验收。软件停机不替代独立安全硬件。
- 控制权状态机必须明确：安全锁定、人工操作、待人工批准、受限自动执行、故障锁存；开机不自动进入自动运行。
- 执行前二次检查设备状态、工艺范围及建议时效；执行后以实测转速/时长记录实际动作；指令接受不是动作完成。
- 不建议直接引入强化学习或复杂MPC。先采用“可信状态 + 专家约束 + 有界参数推荐”，只有在真实对照证明有效后再迭代。

**闭环判定标准：** 状态观测发生变化 → 产生不同的合法决策 → 执行器实际完成动作 → 下一轮感知/事件反馈可追溯，并且异常路径安全回退。不能仅因滚筒能定时调速就宣称状态驱动闭环。

### 3.7 G6｜A/B/C对照、消融和成茶品质

比较组建议：

| 组别 | 控制策略 | 用途 |
|---|---|---|
| A 人工经验 | 由有经验师傅操作 | 现实工艺参考 |
| B 固定程序 | 预先固定摇青与静置时间/转速 | 验证是否优于简单自动执行 |
| C 状态驱动 | 已冻结版本的建议/人工确认或受限自动控制 | 验证实际增量价值 |

设计要求：

1. 实验前固定**主要终点**，例如盲评综合品质分数或批次间波动；同时明确次要终点：香气分项、工艺偏差、人工干预、时间/能耗、失败率等。只选一个主要终点，防止事后挑结果。
2. 相同品种/香型、采摘批次、嫩度、鲜叶初始状态下分组；优先采取**同批鲜叶匹配分样、随机分配处理、分区组重复**，记录设备间可能的混杂因素。
3. 完整做青后保持后续杀青、揉捻、干燥等工序尽可能一致，避免后处理差异被误认为做青控制效果。
4. 感官评价应有多位评分者、盲样编码、明确评分规则；可获得条件下加入理化/VOC或专业检测，但便宜MOS指纹不能替代成茶化学成分定量。
5. 小规模试验只用于检验可行性与估计变异度；正式样本量依据主要终点变异度、实际效应大小和统计功效计算，不能以秒级测量点数当作独立重复。
6. 将模型版本和决策规则在对照开始前冻结，事后不得根据测试组结果追改算法再声称同一轮盲测有效。
7. 主要报告各组样本量、均值/离散度、组间效应量和置信区间、失败与缺失、显著性/不确定性；负结果和异常样本保留。

**重要：** 模型识别准确率上升≠茶叶品质提升；在线监测成功≠自适应控制成功；试验次数少且未控制批次差异时，不宣称品质更稳定。

### 3.8 G7｜作品交付、现场演示与应用验证

## 4. 数据规范、指标与复现实验

### 4.1 最低批次字段

| 类别 | 最低字段/内容 |
|---|---|
| 身份 | batch_id、session_source（simulation/physical）、日期与时区、原料来源、品种香型、操作者、设备ID |
| 版本 | 固件/上位机/模型版本、Git SHA、标定/SOP/量表版本 |
| 时间 | 主机接收时间、MCU时间、seq、事件时间、采样与清洗状态 |
| 感知 | 每路MOS原始值+标志、环境温湿度、质量g、（接入后）叶温/图像 |
| 执行 | 动作建议、人工批准/否决、设备命令状态、目标/实际RPM、开始/结束、故障 |
| 标签 | 记录人、相对事件位置、阶段与等级、可信度、备注、修订链 |
| 质量 | 帧完整性、缺失标记、故障时间窗、图像索引、原始数据哈希 |
| 结果 | 盲评编码、品质评分表、理化检验ID、对应对照组与随机化记录 |

数据使用现有主机批次格式扩展。对于不同频率的VOC采样和图像采集，独立保留真实采样时刻和关联窗口；无样本时使用缺失值，不插值制造真实观测。

### 4.2 计算口径

- 采集完整率 = 有效记录数 / 预期记录数，分母必须写明采样间隔和中断定义；并单列物理设备实际发出/主机接收/文件写入计数。
- MOS重复性CV = 同定义响应特征的标准差 / 均值（均值接近0时不能直接用CV）；先定义响应基线、时间窗口和是否取绝对值。
- 相对质量损失 r(t) = [m0 - m(t)] / m0，需注明m0选择、容器质量、去皮和稳定窗口。它不等同叶片实际含水率。
- 质量变化速率建议仅在有效静置窗口计算，并标明滤波时间窗；滚筒转动时的称重不直接外推。
- 漂移/湿度补偿效果至少报告**补偿前后**在独立条件下的偏差、方差和失败时段。
- 状态模型同时报告按批次分组的总体指标与各批次指标，防止大批次挤占平均值。
- 品质稳定性优先用独立成茶批次的评分离散度评估；必须说明批次间原料和环境差异。

### 4.3 复现与归档

原始数据目录只读、永不覆盖；处理结果放入版本化的processed/reports目录，至少记录脚本SHA、配置、来源批次、训练/测试分组、随机种子、输出哈希和运行环境。默认不将大量原始茶样数据、个人信息、合作方商业记录和可识别图片直接提交公开GitHub；公开仓库提交脱敏样例、数据字典和可复算脚本，受限原始数据单独备份。

## 7. 阶段决策规则与风险处置

| 触发问题 | 处理与降级方案 |
|---|---|
| 湿度干扰/气路残留显著 | 延长清洗、缩小可用环境范围、报告无效样本；未解决前不让VOC单独决定动作 |
| 真实做青批次数不足 | 先提供可靠的数据记录和专家辅助系统；不宣称跨批次模型有效 |
| 视觉/叶温尚未到位 | 明确报告当前可用模态，继续VOC+环境+称重路线；不得补造数据 |
| 状态模型不胜过时间/规则基线 | 保留负结果、分析标签和任务定义，优先改实验设计而非堆更复杂AI |
| 低置信度或分布外鲜叶 | 拒绝自动建议、提示人工复核；不把模型分数当安全认证 |
| 电气互锁或停机时间不达标 | 禁止自动执行，只保留旁路监测、影子建议和人工控制 |
| 品质无显著改善/更不稳定 | 如实公布效应量与置信区间，收敛到过程可追溯或辅助决策价值，不包装为已实现品质提升 |
