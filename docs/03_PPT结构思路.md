# 青韵智控 PPT 结构思路（按官方汇报模板适配）

本文件依据第十五届“挑战杯”中国大学生创业计划竞赛官方汇报模板，结合“青韵智控——凤凰单丛做青多模态感知与自适应控制系统”的当前研发阶段，对答辩结构重新设计。

官方汇报模板要求围绕 8 个部分呈现：

1. 项目背景
2. 项目概述
3. 项目优势
4. 项目应用
5. 社会价值
6. 商业模式
7. 团队介绍
8. 未来展望

本项目仍处于研发与验证阶段，因此正式材料必须严格区分“已完成”“正在进行”“计划验证”，不得把计划、预测或目标写成既有成果。

---

## 1. 官方硬约束

- 正文须围绕上述 8 个部分展开，确无内容可对应删减，但整体逻辑必须完整。
- 正文页数不含封面、封底，控制在 20 页以内。
- 页面比例统一为 16:9。
- 国赛初审上传 PDF，文件控制在 30 MB 以内。
- 国赛终审使用 PPT，文件控制在 150 MB 以内。
- 设计遵循“简洁、实用、清晰”，作品内容优先，不追求过度视觉化、艺术化。
- 不使用复杂动效、3D 渲染、特效字体等形式掩盖内容不足。
- 标题规范准确，不使用谐音式、噱头式、不规范表达。
- 所有说明页与官方模板提示文字在正式提交时删除。

当前建议版本：**18 页总页数，其中封面 1 页、正文 16 页、封底 1 页。**

---

# 2. 整体答辩逻辑

官方 8 部分不是 8 个彼此独立的章节，而要串成一条证据链：

> 真实产业问题 → 项目定位与作品形态 → 核心技术与差异化 → 研发/应用证据 → 社会与产业价值 → 可持续商业路径 → 团队能力 → 未来一年与三年计划

评委最终需要快速判断：

1. 问题是否真实；
2. 作品是否做得出来；
3. 技术是否比已有方案前进一步；
4. 是否有实物、实验和真实应用证据；
5. 是否具备进一步产业化的可能；
6. 团队是否真正具备完成项目的能力。

项目名：**青韵智控**  
副标题：凤凰单丛做青多模态感知与自适应控制系统

# 一、项目背景

## P2｜做青已实现机械化，但关键判断仍高度依赖经验

必须让评委相信：这是一个真实、具体、值得解决的问题。

核心内容：

- 做青对乌龙茶香气和品质形成的重要性；
- 当前设备可以完成摇青、温湿度控制等“动作执行”；
- 但“什么时候摇、摇多强、摇多久、何时结束”仍大量依赖制茶师傅经验。

避免：只讲宏观茶产业规模，不落到具体工艺矛盾。

## P3｜现有方案解决了“自动执行”，尚未解决“状态驱动决策”

用已有论文 / 设备 / 文献形成对比：

- 已有：自动摇青、电子鼻阶段识别、视觉识别、环境监测；
- 缺口：多模态状态表征、跨批次稳定性、工艺决策闭环、最终品质验证。

结论：

> 本项目不是再做一台自动摇青机，而是让实时鲜叶状态真正进入控制决策。

---

# 二、项目概述

## P4｜项目定位：以鲜叶状态为核心的做青感知与控制系统

一句话定义：

> 将香气、视觉、失水、叶温和环境信息转化为实时状态，并用于指导做青时机和参数调整。

展示项目整体框架：

鲜叶 → 多模态感知 → 状态估计 → 工艺决策 → 执行 → 品质反馈。

## P5｜作品形态与当前研发进度

这页必须逐步从“想法”转向“作品”。

建议展示：

- 感知端：电子鼻、相机、称重、叶温、温湿度；
- 采集与计算端：STM32 / ESP32 + 上位机 / 边缘计算；
- 执行端：小型滚筒 / 电机 / 调速控制；
- 软件端：数据采集、状态估计、控制建议、加工档案。

当前没有完成的内容必须标记：**待研发 / 待实测 / 待验证**。

---

# 三、项目优势

## P6｜核心技术一：多模态做青状态表征

解释为什么不能只靠一个电子鼻：

- VOC：反映香气和挥发物变化；
- RGB：反映叶缘红变、色泽、卷曲与纹理；
- 失水：反映物理脱水过程；
- 叶温 / 环境：反映热湿状态并辅助补偿传感器漂移。

强调：多模态不是“堆传感器”，而是减少单一信号的盲区。

## P7｜核心技术二：低成本电子鼻的稳定在线采样

重点讲工程问题：

- MOS 阵列输出整体 VOC 指纹，而非单一物质浓度；
- 采样 / 清洗气路；
- 温湿度补偿；
- 基线漂移与长期校准；
- 传感器阵列优化。

这一页需要实物板卡、气路图和真实响应曲线逐步替换示意图。

## P8｜核心技术三：从固定时间控制转向状态驱动控制

左侧：固定程序

> 到时间 → 摇青 → 固定参数

右侧：本项目

> 实时状态 → 判断是否进入下一阶段 → 决定时机 / 强度 / 持续时间 / 静置时间

第一代策略：

> 状态估计 + 规则约束 + 人工确认

不要一开始把项目包装成“全无人、全 AI、自主制茶”。

## P9｜与已有方案相比，创新在“闭环”而不是单点技术

建议做竞品 / 文献能力矩阵：

| 能力 | 自动摇青设备 | 电子鼻阶段识别研究 | 本项目目标 |
|---|---|---|---|
| 自动执行 | 有 | 无 | 有 |
| VOC 在线监测 | 部分 | 有 | 有 |
| 视觉 / 失水融合 | 少 | 少 | 有 |
| 跨批次校准 | 少 | 部分 | 重点验证 |
| 状态驱动控制 | 以固定程序为主 | 无 | 重点验证 |
| 成茶品质闭环验证 | 部分 | 少 | 重点验证 |

所有“有 / 少 / 部分”等判断正式赛稿前必须用具体论文、专利或产品证据核验。

# 四、项目应用

## P10｜研发验证路径：先监测，再半自动，最后闭环

阶段 1：在线监测 + 状态推荐  
阶段 2：人工确认 + 半自动控制  
阶段 3：状态驱动自适应控制

说明为什么这样做：

> 先证明传感与状态判断可靠，再逐步扩大自动控制范围，降低做坏茶叶的风险。

## P11｜三组对照实验验证项目有效性

A 组：老师傅传统做青  
B 组：固定程序自动做青  
C 组：状态驱动自适应做青

评价三层：

- 过程：阶段识别、最佳时机误差、失水估计；
- 品质：感官、关键 VOC、理化指标；
- 工程：批次波动、人工干预、能耗、成本。

**当前尚无数据的指标只能写“验证方案”，不得制作虚假结果图。**

## P12｜真实应用 / 小试 / 中试证据页

官方模板明确要求展示项目应用、小试或中试、行业认可、落地进展及应用效果。

当前阶段建议保留为“证据占位页”，后续必须优先补充：

- 茶厂 / 合作社真实试验；
- 制茶师傅访谈与使用反馈；
- 样机连续运行记录；
- A/B/C 三组成茶照片；
- 应用证明 / 合作意向 / 试用评价。

没有真实证据前，统一标记“待补充”，不要包装成已落地。

# 五、社会价值

## P13｜将个体经验沉淀为可记录、可验证、可复用的数字工艺

价值逻辑：

传统：

> 个人经验 → 口传心授 → 难量化 → 难复制

数字工艺：

> 师傅经验 + 过程数据 → 状态模型 → 工艺参数 → 批次档案 → 持续迭代

建议从以下角度展开：

- 辅助传统制茶经验传承；
- 提高批次稳定性；
- 为中小茶企提供低成本数字化工具；
- 沉淀凤凰单丛加工数据资产；
- 服务广东特色茶产业数字化升级。

正式赛稿中，社会价值必须尽可能用真实应用数据支撑。

# 六、商业模式

## P14｜目标客户、应用场景与市场定位

建议先验证最直接的客户：

- 凤凰单丛生产企业；
- 专业合作社；
- 有现成摇青设备、希望做数字化改造的加工点；
- 茶叶科研 / 教学机构。

市场数据必须引用可靠来源；不得用未经核验的“千亿市场”“巨大蓝海”等表述。

## P15｜商业路径：设备 + 改造 + 服务（当前为待验证假设）

可作为早期商业模式假设：

1. 感知与采集设备销售；
2. 现有做青设备数字化改造；
3. 软件 / 数据分析 / 维护服务；
4. 面向科研与教学的实验平台。

必须注明：以上为**待通过用户访谈、成本核算和真实试点验证的商业假设**。

正式商业页后续需补：

- BOM 与样机成本；
- 目标售价区间；
- 毛利与维护成本；
- 销售 / 合作渠道；
- 财务预测依据；
- 如无融资和公司，不虚构相关内容。

# 八、未来展望

## P17｜一年与三年路线：产品、市场、团队、资金和风险一起讲

### 未来一年

- 完成第一代多模态采集样机；
- 完成多批次做青数据集；
- 建立三组对照实验；
- 完成半自动控制原型；
- 推进茶厂 / 合作社试用；
- 根据真实结果申请专利 / 论文 / 软著等成果。

### 未来三年

- 扩展多茶季、多品种验证；
- 形成可改造现有设备的模块化产品；
- 建立更多真实茶厂应用样本；
- 逐步完善工艺数据库和服务体系。

融资需求、营收目标、团队规模等在没有充分依据时只保留“待评估 / 待验证”，不得直接填夸张数字。

同时展示主要风险：

- 技术：MOS 漂移、跨批次泛化、样本不足；
- 市场：茶企采购意愿、维护复杂度；
- 供应链：传感器一致性与成本；
- 工艺：错误控制可能影响整批茶叶品质。

每个风险必须有对应预案。

# 4. 页面视觉规范

整套 PPT 采用浅绿色 / 茶绿色视觉体系，但官方模板明确要求内容优先，因此视觉原则调整为：

- 浅绿色作为背景与辅助色，深绿色作为标题 / 强调色；
- 少量暖金 / 橙色用于做青关键节点或对比；
- 不把每页做成“海报”；
- 主图优先使用真实项目照片、真实实验图、真实数据图；
- 图表、结构图统一线宽、圆角、字号和配色；
- 不使用无意义 AI 大脑、科技粒子、3D 芯片等装饰；
- 不使用复杂入场动画；
- 每页只承担 1 个核心判断。

建议标题：30–34 pt  
正文：18–22 pt  
图注 / 来源：11–14 pt

# 5. 正式赛稿前的替换清单

必须逐步把“概念型页面”替换为“证据型页面”：

- P2：真实茶厂 / 师傅调研；
- P3：已有研究与竞品证据；
- P5：团队真实样机；
- P7：真实电子鼻与响应曲线；
- P9：查新 / 竞品矩阵；
- P11：真实三组实验数据；
- P12：真实应用 / 小试 / 中试；
- P14：真实客户访谈和市场数据；
- P15：真实 BOM、成本和商业验证；
- P16：真实团队分工与成果；
- P17：基于真实进度制定的一年 / 三年目标。

最终原则：

> **背景让评委理解问题，技术让评委理解作品，实物让评委相信做出来了，实验让评委相信有效，应用让评委相信值得继续。**
