# 一、固定视觉风格

## 1.1 总体气质

关键词：**白底、茶绿、科研答辩、信息密度适中、卡片化、证据导向**。

参考用户确认的高分答辩 PPT 版式逻辑，但不复制其文字、色彩和具体排版。

统一规则：

- 页面背景：白色或极浅灰绿色；
- 主色：深茶绿；
- 辅色：中茶绿、浅茶绿；
- 正文：深灰黑；
- 不使用蓝色作为主色；
- 不使用红色作为常规强调色；
- 全页最多使用 3 个绿色层级；
- 所有卡片、线框、图标均属于同一绿色体系。

## 1.2 页面骨架

正文页统一：

- 左上角使用 `1.1｜项目背景`、`2.2｜系统架构` 这样的章节编号；
- 右上角保留简洁导航条，当前章节用深茶绿高亮；
- 不再放置贯穿全页的大项目标题；
- 标题下方可以有一行“本页核心结论”，但不使用大面积横幅；
- 正文以 2–4 个卡片 / 图表模块构成；
- 底部可保留极细页码和项目简称；
- 每页最多一个重点大图，其余为辅助信息。

## 1.3 信息表达规则

每一页只回答一个核心问题：

> 评委看完这一页，应该相信什么？

页面优先顺序：

**结论标题 → 证据 / 图 → 简短解释 → 页底结论。**

禁止：

- 一页塞满 8–10 个小模块；
- 连续多页都是纯流程图；
- 大段文字；
- 为“高级感”使用玻璃拟态、霓虹、复杂 3D；
- 使用尚未验证的数据作为结果；
- 生成式图片冒充真实茶厂、真实样机或真实应用。

# 第一部分｜项目背景

## P2｜1.1 项目背景：做青的关键判断仍高度依赖经验

本页核心结论：

> 做青不是简单“摇一摇”，其关键在于根据鲜叶实时状态决定何时摇、摇多久、何时停。

建议内容分三块：

1. **工艺关键性**：做青直接影响凤凰单丛香气形成与品质稳定；
2. **经验依赖**：师傅依靠闻香、看色、触叶、感受失水程度综合判断；
3. **现实问题**：原料、天气、批次变化使固定经验难以稳定复制。

页底结论：

> 当前真正缺少的不是“会转的机器”，而是“能看懂鲜叶状态的系统”。

---

## P3｜1.2 现有自动化的边界：能执行，但不会根据鲜叶变化自主调整

本页核心结论：

> 已有设备解决了动作机械化，已有研究证明状态可以被感知，但二者尚未形成稳定的状态驱动闭环。

内容：

- 自动 / 控制做青设备：可完成定时、调速、环境控制；
- 电子鼻研究：已证明 VOC 变化能够反映乌龙茶加工阶段；
- 视觉 / 环境监测：能够提供部分状态信息；
- 关键缺口：**多模态融合、跨批次稳定、实时决策、品质闭环验证**。

建议做“已有能力—未解决问题”二维矩阵，而不是文献截图墙。

# 第二部分｜项目概述

## P4｜2.1 项目概述：把鲜叶状态变成可测、可判、可控的过程变量

一句话定义：

> 青韵智控通过 VOC、视觉、失水、叶温和环境信息连续感知鲜叶状态，再将状态用于做青参数决策。

主图：

**鲜叶 → 多模态感知 → 状态估计 → 工艺决策 → 执行 → 品质反馈**

下方只解释三个输出：

- 当前处于什么状态；
- 是否需要进入下一次摇青；
- 建议如何调整时机、强度、时长和静置时间。

---

## P5｜2.2 作品形态：感知端、采集端、决策端、执行接口组成一套系统

本页重点从“概念”转向“作品”。

四个模块：

1. **感知端**：MOS 电子鼻、RGB、称重、叶温、温湿度；
2. **采集端**：ESP32-S3 / ADC / 上位机；
3. **决策端**：状态估计、置信度、工艺建议；
4. **执行接口**：电机转速、摇青时长、静置时间等控制参数。

右下角给出当前研发状态：

- 已设计
- 开发中
- 待实测
- 待闭环验证

不要把未完成部分写成已经实现。

# 第三部分｜项目优势

## P6｜3.1 多模态感知：不同信号共同描述同一片鲜叶

本页回答：为什么不能只用电子鼻？

四类信号：

- VOC：香气与挥发性成分变化；
- RGB：叶缘红变、色泽、卷曲和纹理；
- 质量 / 失水：物理脱水程度；
- 叶温 + 环境：热湿状态和传感器补偿依据。

核心观点：

> 多模态的价值不是增加传感器数量，而是降低单一信号失真或失效造成的误判。

后续必须用消融实验验证这一点。

---

## P7｜3.2 电子鼻工程化：重点不是“闻到”，而是稳定地连续闻

本页以真实硬件和气路为核心。

内容：

- 4–6 路低成本气敏阵列；
- 采样 / 清洗双通路；
- 固定流量和采样腔；
- 温湿度同步采集；
- 基线、漂移、恢复时间记录；
- 通道筛选和长期校准。

核心表述：

> MOS 阵列用于构建综合色指纹，不把单个传感器错误解释为某一种 VOC 的定量检测。

正式版本逐步替换为真实板卡、气路照片和真实响应曲线。

---

## P8｜3.3 状态估计：把师傅的综合判断转成可解释状态

本页输出建议固定为：

- 做青阶段；
- 香气发展水平；
- 失水程度；
- 叶缘红变 / 视觉变化；
- 综合成熟度；
- 模型置信度。

模型第一阶段不追求复杂深度网络，优先采用：

- PCA / PLS；
- LDA；
- Random Forest / XGBoost；
- 轻量时序模型。

页面强调：

> 低置信度时回退到人工确认，而不是强行自动控制。

---

## P9｜3.4 自适应控制：从“按时间摇”变成“看状态再决定”

左右对比：

传统固定程序：

> 预设时间 → 固定转速 → 固定时长 → 固定静置

本项目：

> 实时状态 → 判断是否需要摇青 → 决定转速 / 时长 → 决定静置时间 → 再感知

第一代闭环：

**规则约束 + 状态估计 + 人工确认。**

不使用“完全无人制茶”“AI 替代老师傅”等夸张表述。

---

## P10｜3.5 创新边界：创新在“状态进入控制回路”

建议做能力矩阵，比较：

- 传统人工做青；
- 固定程序自动设备；
- 电子鼻在线监测研究；
- 青韵智控。

比较维度：

- 自动执行；
- VOC 在线感知；
- 视觉 / 失水融合；
- 跨批次校准；
- 状态驱动决策；
- 成茶品质验证。

页面底部只保留三项创新：

1. 多模态鲜叶状态表征；
2. 跨批次 / 跨环境自校准；
3. 品质导向的状态驱动控制。

所有竞品和研究结论正式赛稿前必须逐项核验来源。

# 第四部分｜项目应用

## P11｜4.1 验证路线：先可靠感知，再进入控制

路线分三级：

### 阶段 A｜在线监测

传感器连续采集，输出状态和趋势，不控制设备。

### 阶段 B｜人工确认的半自动

系统给出建议，师傅确认后执行。

### 阶段 C｜自适应闭环

在安全边界内自动调整摇青和静置参数。

本页同时展示当前所处阶段，避免把规划包装成成果。

---

## P12｜4.2 实验验证：最终比的是成茶品质和批次稳定性

三组对照：

- A：老师傅传统做青；
- B：固定程序自动做青；
- C：状态驱动自适应做青。

评价三层：

### 过程层

状态识别、时机判断、失水估计、人工干预次数。

### 品质层

感官审评、关键 VOC、茶多酚 / 氨基酸等理化指标。

### 工程层

批次离散度、连续运行、能耗、成本、维护复杂度。

当前未获得的数据只展示实验设计，不制作“预计提升 xx%”的结果图。

# 第五部分｜社会价值

## P13｜5.1 从“口传经验”到“可积累的数字工艺”

主线：

传统：

> 师傅经验 → 当场判断 → 难记录 → 难复制

本项目：

> 师傅经验 + 过程数据 → 状态模型 → 工艺参数 → 批次档案 → 持续迭代

价值聚焦：

- 辅助传统制茶经验传承；
- 提升批次一致性；
- 为中小茶企提供可逐步改造的数字化方案；
- 积累凤凰单丛加工过程数据；
- 为后续其他乌龙茶工艺适配提供基础。

避免空泛堆砌“乡村振兴”“产业赋能”。

1. 凤凰单丛茶企 / 合作社；

- 数据分析 / 校准 / 维护服务；

# 第七部分｜未来展望

## P15｜7.1 未来一年与三年：从 MVP 到真实生产验证

建议只做一条清晰时间轴。

### 未来一年

- 完成感知 MVP；
- 完成多批次真实做青采集；
- 建立状态估计模型；
- 完成半自动系统；
- 完成 A/B/C 对照；
- 获取至少一个真实茶厂 / 合作社试点。

### 三年方向

- 跨茶季 / 跨批次稳定；
- 适配更多单丛或乌龙茶品类；
- 形成模块化改造产品；
- 建立长期工艺数据库；
- 推进专利、论文、软著和产业合作。

同步列出三类风险：

- 传感器漂移与湿度干扰；
- 不同原料 / 茶季的泛化；
- 客户接受度与维护成本。

所有融资、营收、客户数量只在有依据后加入。
