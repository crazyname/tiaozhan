# 青韵智控 MVP 硬件与第一阶段实验方案

> 目的：把当前“多模态感知 + 状态估计 + 自适应控制”的概念，拆成一套本科团队可以在短周期内搭建、采集真实数据并逐步迭代的最小可行系统（MVP）。
>
> 本文件定义的是**研发计划与候选方案**，不是已经完成的成果。器件型号、价格、性能指标均需在采购与预实验后更新为真实记录。

---

# 1. 第一阶段只解决什么问题

第一阶段不要同时追求“完整自动做青 + 高精度 AI + 茶厂量产”。

MVP 只需要回答 4 个问题：

1. VOC、视觉、失水、叶温、环境信息能否**稳定同步采集**；
2. 多路 MOS 传感器能否对做青过程形成**可重复的动态响应轨迹**；
3. 不同模态是否能提供互补信息，而不是简单堆传感器；
4. 是否能形成一套可供后续状态估计与控制使用的**完整批次数据链**。

第一阶段系统定位：

> **旁路在线监测系统 + 数据采集平台**

暂不直接接管做青过程。

只有在“采集可靠、标签可靠、状态估计可靠”之后，才进入半自动控制和闭环控制。

---

# 2. MVP 总体架构

```text
鲜叶 / 做青环境
      │
      ├── VOC 样气 ──> 气路 ──> MOS 阵列 ──> ADC ──┐
      ├── RGB 图像 ───────────────────────────────┤
      ├── 实时质量 ──> 称重传感器 ────────────────┤
      ├── 叶面温度 ──> 红外温度 ──────────────────┤
      └── 温湿度 ─────────────────────────────────┤
                                                   │
                                             MCU / 边缘采集
                                                   │
                                             时间戳同步
                                                   │
                                              上位机记录
                                                   │
                  ┌────────────────────────────────┼───────────────────────────────┐
                  │                                │                               │
               原始数据                        实时曲线                        事件标记
                  │                                │                               │
                  └────────────────────────────────┴───────────────────────────────┘
                                                   │
                                              批次数据库
                                                   │
                                              状态估计模型
                                                   │
                                      后续：工艺建议 / 控制策略
```

核心原则：

- 所有模态统一时间戳；
- 原始数据永久保存，特征数据可以重算；
- 第一阶段尽量少做不可逆硬件设计；
- 优先保证重复性，而不是外观完整度。

# 3. 第一版硬件模块

## 3.1 VOC / 电子鼻模块

### 第一版目标

建议先做 **4–6 路 MOS 阵列**，不要一开始堆到十几路。

理由：

- 第一阶段任务是确认信号是否稳定、有区分度；
- 路数过多会增加供电、发热、ADC、气路和标定复杂度；
- 后续可根据相关性、特征重要性和重复性删除冗余通道，再决定是否扩展。

### 候选传感器方向

可优先从以下系列筛选：

- Figaro TGS 系列 MOS；
- MEMS MOS 气敏传感器；
- MQ 系列仅作为低成本预研与对比，不建议直接作为最终竞赛样机的全部核心阵列。

选择时重点比较：

1. 对不同有机挥发物响应差异；
2. 响应 / 恢复时间；
3. 湿度敏感性；
4. 基线稳定性；
5. 批次一致性；
6. 长期供货；
7. 单价；
8. 加热功耗。

### 重要边界

MOS 阵列输出应定义为：

> **做青过程 VOC 综合响应指纹**

不得直接把某一路电压解释成“某一种香气分子浓度”。

---

## 3.2 MOS 采集电路

第一版建议：

- ESP32-S3 / STM32：底层采集、阀泵控制、时间同步；
- 16 bit 外置 ADC：提高多路模拟量采集稳定性；
- 多通道 ADC 不够时可使用 2 片或多路模拟切换；
- 单独规划传感器加热电源和模拟采样电源；
- 模拟地、数字地和电机 / 气泵噪声源做好布线隔离；
- 每个通道保留测试点。

第一版不急于做完整自研 PCB，可先使用模块 + 洞洞板 / 简单转接板验证。

进入第二版后再做：

- 统一 PCB；
- 稳压与滤波；
- 保护；
- 模拟前端；
- 接插件；
- EMC / 噪声优化。

# 4. 气路系统

电子鼻能否用于真实做青现场，气路设计的重要性不低于算法。

## 4.1 推荐采用旁路采样

不让传感器板直接长期暴露在滚筒高湿、高粉尘和复杂温度环境中。

建议：

```text
做青空间取样点
    ↓
防叶片 / 大颗粒过滤
    ↓
取样管
    ↓
三通 / 电磁阀
    ↓
传感器气室
    ↓
气泵
    ↓
排气
```

另设洁净空气清洗支路：

```text
洁净空气
   ↓
清洗阀
   ↓
传感器气室
   ↓
气泵
```

## 4.2 材料原则

接触样气的管路尽量：

- 短；
- 内壁光滑；
- 低吸附；
- 易更换；
- 易清洗。

正式样机优先考虑 PTFE 等低吸附材料。

## 4.3 采样周期初始建议

第一轮预实验可从以下周期起步：

1. 清洗 / purge：120–300 s；
2. 基线稳定：30–60 s；
3. 样气采集：60–120 s；
4. 恢复：120–300 s。

实际周期必须根据传感器响应曲线调整，不能把上述时间当作固定标准。

目标不是采样越快越好，而是：

> 上一轮样气不能明显污染下一轮结果。

# 5. 环境与叶温

## 环境温湿度

候选：SHT31 / BME280 或同等级数字温湿度传感器。

用途：

- 记录加工环境；
- 建立 MOS 湿度补偿；
- 分析失水状态；
- 识别批次差异。

## 叶温

第一版可使用非接触红外温度传感器。

要求：

- 固定距离；
- 固定视场；
- 记录安装位置；
- 避免把环境背景温度误当叶温。

如果实际叶面分布差异明显，再考虑红外阵列 / 热像方案。

---

# 6. RGB 视觉模块

第一版优先使用固定机位普通高清相机，不急于采购工业相机。

必须控制：

- 相机位置；
- 拍摄距离；
- 光照；
- 白平衡；
- 背景；
- 曝光参数。

建议建立固定拍摄盒 / 固定补光。

第一阶段图像重点提取：

- RGB / HSV / Lab；
- 叶缘红变比例；
- 综合色差；
- 纹理；
- 卷曲 / 形态；
- 覆盖率。

不要一开始做复杂目标检测模型。

---

# 7. 称重 / 失水模块

建议：

- 5–20 kg 量程称重传感器；
- HX711 或更高性能称重 ADC；
- 机械结构避免侧向受力；
- 上电后做零点和标准砝码标定。

输出：

- 当前质量；
- 相对初始质量；
- 失水率；
- 失水速率。

建议失水率定义统一：

```text
loss_ratio = (m0 - mt) / m0
```

其中：

- `m0`：本批次统一定义时刻的初始质量；
- `mt`：当前质量。

必须在 SOP 中明确 `m0` 取值时间，否则不同批次无法比较。

# 8. 上位机与数据记录

第一版目标不是做炫酷 UI，而是保证数据完整。

最低要求：

- 实时显示各通道；
- 保存原始数据；
- 手动事件标记；
- 批次编号；
- 设备状态；
- 异常日志；
- 数据导出。

推荐 CSV + 图片 + JSON 元数据组合。

## 主数据表建议字段

```text

elapsed_s
```

# 10. 第一阶段实验设计

第一阶段不要直接拿整批凤凰单丛去做闭环控制。

先按“传感器 → 系统 → 茶叶”逐级验证。

---

## E0｜电气与数据链路稳定性

目标：

- 连续运行 4–8 h；
- 无明显丢包；
- 无 MCU 重启；
- 时间戳连续；
- ADC 无异常跳变；
- 气泵 / 阀动作不会导致模拟量大幅干扰。

必须记录：

- 供电电压；
- 传感器基线；
- MCU 状态；
- 丢包数；
- 故障时间点。

---

## E1｜MOS 重复性实验

目标：验证同一稳定气味源重复采样时，响应是否可重复。

流程：

1. 每次使用相同参考气味源；
2. 固定温湿度；
3. 固定采样 / 清洗周期；
4. 连续重复 ≥10 次；
5. 计算峰值、稳态值、响应斜率、积分面积等特征；
6. 比较各通道重复性。

建议记录：

- 均值；
- 标准差；
- 变异系数 CV；
- 漂移趋势。

第一版目标阈值可暂设 CV < 10% 作为工程参考，但最终阈值应以预实验和传感器特性确定。

---

## E2｜湿度干扰实验

目标：确认湿度变化会对哪些 MOS 通道造成多大影响。

至少设置 3 个湿度区间，例如：

- 低；
- 中；
- 高。

不强制追求精确标准湿度环境，第一轮重点是识别趋势。

测试：

- 洁净空气基线；
- 相同气味源；
- 不同湿度条件。

输出：

- 各通道湿度敏感程度；
- 是否需要湿度补偿；
- 哪些通道在高湿下不稳定。

---

## E3｜清洗 / 恢复实验

目标：确定采样后需要清洗多久才能回到可接受基线。

记录：

- 采样结束时响应；
- 清洗后 30 / 60 / 120 / 180 / 300 s；
- 与原基线的偏差。

最后确定：

- 最短安全清洗时间；
- 是否存在明显记忆效应；
- 哪些通道恢复过慢。

---

## E4｜称重与失水标定

目标：确认连续称重在实际做青环境中稳定可用。

测试：

- 多点砝码标定；
- 长时间零点漂移；
- 温度变化；
- 机械振动影响；
- 摇青前后稳定时间。

做青过程中不要把滚筒强振动时的瞬时称重直接作为有效失水数据。

应设定：

> 静置稳定窗口 → 求平均 → 作为当前有效质量。

---

## E5｜多模态同步采集

目标：确认：

- MOS；
- 温湿度；
- 叶温；
- 重量；
- RGB；
- 工艺事件

能够在同一时间轴上重建。

测试至少连续 4 h。

输出一张统一时间轴图，作为后续 PPT 早期技术证据。

---

## E6｜第一批真实做青被动监测

第一批真实茶叶实验只做：

> **被动采集，不自动控制。**

记录完整做青过程中：

- 每一次摇青开始 / 结束；
- 每一次静置；
- 师傅判断；
- 香气描述；
- 鲜叶状态；
- MOS；
- RGB；
- 失水；
- 叶温；
- 环境。

目标：先确认真实工艺过程是否出现可解释的多模态变化。

---

# 11. 第一阶段验收标准

第一阶段完成不等于“模型准确率达到多少”。

建议验收标准：

## 数据层

- 连续采集 ≥4 h 不丢关键数据；
- 各模态统一时间戳；
- 批次元数据完整；
- 原始文件可追溯。

## 传感层

- MOS 重复性可量化；
- 湿度影响已识别；
- 清洗恢复周期已确定；
- 称重完成标定。

## 工艺层

- 至少完成 1 个完整真实做青过程的被动采集；
- 摇青 / 静置事件全部被记录；
- 师傅判断有结构化标签。

## 工程层

- MVP 有真实照片；
- 有 BOM 与采购记录；
- 有版本号；
- 有故障和失败记录。

达到上述条件后，才进入第二阶段：

> 多批次数据采集 + 状态模型验证。

# 12. 推荐开发顺序

## 第 1 周

- 确定 MOS 候选；
- 搭 ADC + MCU；
- 接温湿度、叶温、称重；
- 建 CSV 记录程序。

## 第 2 周

- 完成气室、气泵、电磁阀；
- 实现自动采样 / 清洗；
- 完成 E0 / E1。

## 第 3 周

- 完成湿度、恢复、称重实验；
- 固定 RGB 拍摄条件；
- 完成 E2 / E3 / E4。

## 第 4 周

- 多模态联调；
- 完成 E5；
- 准备第一次真实茶叶被动采集。

时间可以根据茶季与设备条件调整，不以“4 周必须完成”为硬约束。

# 14. 与挑战杯材料的对应关系

这套 MVP 最终需要为比赛提供的不是“用了哪些传感器”，而是以下证据：

| 比赛问题 | MVP 要提供的证据 |
|---|---|
| 你们真的做了东西吗？ | 样机、PCB / 接线、气路、上位机、现场照片 |
| 电子鼻可靠吗？ | 重复性、湿度、清洗恢复实验 |
| 多模态不是堆传感器吗？ | 后续消融实验 |
| 真实茶叶能用吗？ | 完整做青时间序列 |
| 以后怎么控制？ | 状态估计与工艺事件对应关系 |
| 成本是否可接受？ | 真实 BOM 与采购记录 |

因此第一阶段的每一次失败实验也应保留记录，它们是项目真实研发过程的一部分。
