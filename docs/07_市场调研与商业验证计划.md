# 青韵智控市场调研与商业验证计划

本文件用于把《商业计划书结构模板》中的“市场分析、商业模式、财务分析、项目应用”等要求转化为可执行的调研与验证任务。

当前原则：**先收集证据，再写结论；先验证客户问题，再设计收费方式；先得到真实 BOM 和试用反馈，再做三年财务预测。**

---

# 1. 商业验证要回答的六个问题

正式商业计划书和答辩中，市场与商业部分至少要回答：

1. 谁是最优先的客户？
2. 他们现在怎样完成做青判断与设备控制？
3. 现有方式最痛的成本、波动或管理问题是什么？
4. 青韵智控相比现有设备到底增加了什么价值？
5. 客户是否愿意试用、改造或付费？
6. 设备成本、实施成本和潜在售价之间是否存在可持续空间？

如果这六个问题没有真实证据，就不应提前写“市场前景广阔”“客户需求强烈”“商业模式成熟”。

---

# 2. 第一阶段目标客户假设

以下均为**待验证假设**，不是已有客户结论。

## A 类：凤凰单丛中小型茶企 / 加工作坊

可能需求：

- 降低做青质量对单个老师傅的依赖；
- 记录不同批次的加工过程；
- 提升不同天气、茶季下的工艺稳定性；
- 在不更换整条设备的前提下进行数字化改造。

重点验证：

- 是否真正存在批次稳定性问题；
- 问题造成的实际损失是什么；
- 是否愿意在现有摇青设备上加装感知模块；
- 可接受的安装、维护复杂度。

## B 类：规模化茶企 / 合作社

可能需求：

- 多设备、多班组的工艺标准化；
- 新员工培训；
- 做青过程追溯；
- 生产数据沉淀；
- 质量管理。

重点验证：

- 是否已经存在数字化系统；
- 当前系统能采集哪些参数；
- 谁拥有设备采购与改造决策权；
- 采购周期和试用流程。

## C 类：制茶设备企业 / 自动化集成商

可能需求：

- 为现有摇青 / 做青设备增加状态感知和控制能力；
- 形成差异化产品模块；
- 获得可嵌入的传感、算法和软件方案。

重点验证：

- 更适合整机销售还是模块合作；
- 现有设备接口和改造难度；
- 设备企业更关注成本、可靠性还是算法能力。

## D 类：高校 / 茶叶科研与教学单位

可能需求：

- 做青过程实验平台；
- 多模态数据采集；
- 教学与科研数据记录。

该类可作为早期低风险应用场景，但不能代替真实生产端验证。

# 3. 访谈计划

## 3.1 建议最低访谈量

校赛前建议至少完成：

- 制茶师傅：8–12 人；
- 茶企 / 合作社负责人：8–12 家；
- 设备或自动化相关从业者：3–5 人；
- 茶学 / 食品 / 加工研究人员：3–5 人。

以上是内部工作目标，不应在未完成前写成“已调研”。

## 3.2 第一轮：问题访谈

目的：确认问题是否真实存在，不介绍完整产品，不诱导答案。

建议问题：

1. 一批凤凰单丛做青过程中，最难判断的环节是什么？
2. 什么时候需要依赖老师傅经验？
3. 不同天气、季节、鲜叶状态会怎样调整做青？
4. 新手和熟练师傅之间最明显的差距是什么？
5. 当前摇青设备能调什么参数？哪些参数仍需人工决定？
6. 最近一年是否出现过因做青判断造成的品质波动？
7. 这种波动会带来哪些损失：原料、人工、售价、返工还是品牌影响？
8. 当前是否记录每批茶的做青过程？如何记录？
9. 如果要引入新设备，最担心什么：价格、维护、误判、卫生、占地、学习成本？
10. 哪一种问题如果被解决，最值得付费？

访谈后记录原话，不要只写团队自己的总结。

---

# 4. 第二轮：方案验证

只有完成问题访谈后，再展示 MVP 概念。

建议展示内容：

- 多模态感知终端；
- VOC / 视觉 / 失水 / 叶温实时曲线；
- 当前状态与建议动作；
- 批次加工档案；
- 对现有设备的改造方式。

需要验证：

1. 哪个功能最有价值？
2. 哪个功能客户完全不关心？
3. 客户希望系统“自动控制”还是“辅助决策”？
4. 是否接受第一阶段由人工确认后再执行？
5. 是否允许在现有设备上加装传感器、相机和称重模块？
6. 数据是否需要上传云端？是否存在数据保密顾虑？
7. 一套设备每年需要使用多少批次？
8. 客户期望的维护周期是多少？
9. 是否愿意提供试验场地和鲜叶进行联合验证？
10. 是否愿意签署试用、合作或意向证明？

---

# 5. 第三轮：付费与采购验证

不要直接问“你愿不愿意花 1 万元”。更有效的是比较不同产品包。

## 方案 A：感知辅助版

功能假设：

- VOC；
- 视觉；
- 失水；
- 环境；
- 实时状态；
- 过程记录；
- 人工决策。

验证问题：客户是否愿意单独购买“监测 + 记录”。

## 方案 B：设备改造版

增加：

- 电机 / 变频器接口；
- 摇青时机建议；
- 人工确认后自动执行。

验证问题：客户是否更倾向改造现有设备，而不是购买新整机。

## 方案 C：闭环控制版

增加：

- 状态驱动控制；
- 自动参数调整；
- 安全边界与异常回退；
- 批次模型校准。

该版本必须在真实实验数据充分后再验证，不应在早期作为成熟产品出售。

# 6. 竞品与替代方案调查

正式比赛不能只比较“同类创业项目”，应比较客户真实可选择的替代方案。

建议按以下四类建立竞品矩阵：

| 类型 | 代表产品/方案 | 自动执行 | VOC在线监测 | 视觉/失水 | 状态驱动控制 | 跨批次校准 | 品质验证 | 改造难度 | 价格/成本 | 证据来源 |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|---|
| 人工经验 | 待调研 |  |  |  |  |  |  |  |  |  |
| 固定程序做青设备 | 待调研 |  |  |  |  |  |  |  |  |  |
| 自动/连续做青设备 | 待调研 |  |  |  |  |  |  |  |  |  |
| 电子鼻监测研究/系统 | 待核验 |  |  |  |  |  |  |  |  |  |
| 青韵智控 | 当前研发状态填写 |  |  |  |  |  |  |  |  | 团队实测 |

每一个竞品必须记录：

- 企业 / 论文 / 专利名称；
- 官网或原始来源；
- 核心功能；
- 价格或报价来源；
- 是否真实量产；
- 本项目相对优势；
- 本项目相对劣势。

禁止用没有来源的“国内竞品普遍……”作为正式论据。

# 7. 市场规模计算方法

不要把“中国茶产业总产值”直接写成项目市场规模。

建议使用自下而上的估算方法。

## 7.1 TAM：理论可服务市场

思路：

> 可采用做青数字化设备的乌龙茶加工主体数量 × 合理的平均设备 / 改造价值

所需数据：

- 乌龙茶主要产区加工主体数量；
- 单个主体平均设备数量；
- 更新 / 改造周期；
- 设备平均预算。

## 7.2 SAM：当前产品真正可服务市场

第一阶段建议限定：

> 广东凤凰单丛及周边单丛加工主体中，具有一定机械化基础并愿意进行数字化改造的客户。

## 7.3 SOM：3 年内实际可触达市场

按：

- 团队产能；
- 试点区域；
- 销售周期；
- 合作伙伴；
- 安装与售后能力

推算，而不是简单写 SAM 的 1% 或 5%。

# 9. 小试 / 试用商业验证

正式比赛中，一份真实试用记录的价值通常高于十页市场预测。

每次试用建议记录：

- 日期；
- 地点；
- 企业 / 合作社；
- 设备；
- 鲜叶品种和批次；
- 试用版本；
- 使用时长；
- 系统故障；
- 操作人员；
- 用户评价；
- 希望改进的功能；
- 是否愿意继续试用；
- 是否允许出具应用 / 合作证明。

可量化观察：

- 人工查看次数变化；
- 决策一致性；
- 批次记录完整度；
- 操作时间；
- 误报警；
- 维护时间；
- 成茶评价。

# 10. 商业模式验证顺序

建议按照以下顺序推进：

> 问题是否真实
> → 客户是否在意
> → 产品是否解决
> → 是否愿意试用
> → 是否愿意付费
> → 愿意为何种版本付费
> → 交付成本是否可接受
> → 是否可以复制

不要倒过来先设计“硬件销售 + SaaS + 数据服务 + 平台生态”。

# 11. 校赛前最低商业证据包

建议至少形成：

- 15–25 份有效访谈记录；
- 3–5 个重点客户深访案例；
- 1 份竞品矩阵；
- 1 份真实 BOM；
- 1 套明确的目标客户画像；
- 1 个可解释的 TAM / SAM / SOM 估算过程；
- 至少 1 个真实试验 / 试用场景；
- 至少 1 份师傅或企业书面反馈（条件允许时）；
- 产品方案 A/B/C 的需求偏好记录；
- 初步价格敏感度与维护需求记录。

所有数量最终以实际完成情况为准。

# 13. 数据使用原则

正式材料中的市场和商业数据分三级：

### A 级：可直接使用

- 政府 / 统计部门；
- 行业协会；
- 企业官方；
- 真实合同 / 报价；
- 团队原始调研；
- 可追溯论文 / 报告。

### B 级：谨慎使用

- 主流媒体；
- 有明确方法说明的行业研究机构；
- 电商公开价格。

### C 级：不能作为关键结论唯一证据

- 无来源自媒体；
- 搜索摘要；
- 二手转载；
- AI 自动生成的市场规模；
- 无法验证的所谓“行业数据”。

最终目标不是让商业章节“数字很多”，而是让每一个关键数字都能回答：**它从哪里来，为什么可信，它如何影响我们的产品决策。**
