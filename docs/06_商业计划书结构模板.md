# 青韵智控商业计划书结构模板

本文件依据第十五届“挑战杯”中国大学生创业计划竞赛商业计划书模板，并结合“青韵智控——凤凰单丛做青多模态感知与自适应控制系统”当前研发阶段进行适配。

正式撰写时必须遵守一个原则：**所有成果、市场数据、财务数据、应用进展、融资情况均如实填写；没有的数据写“待验证 / 待补充”，不得虚构。**

---

# 一、执行摘要

官方要求：800 字以内。

建议最后撰写，压缩以下内容：

1. 项目解决什么问题；
2. 产品 / 服务是什么；
3. 核心技术优势；
4. 当前研发 / 应用进展；
5. 目标客户与市场定位；
6. 商业模式；
7. 团队优势；
8. 财务与融资概况。

推荐一句话定位：

> 青韵智控面向凤凰单丛做青过程中状态难感知、经验难量化、工艺难自适应的问题，构建融合 VOC、视觉、失水、叶温与环境信息的多模态感知系统，并探索基于实时鲜叶状态的自适应做青决策与控制。

当前没有真实营收、融资、客户数量时，不要在执行摘要中人为制造数据。

---

# 二、项目概述

## 2.1 项目背景

应回答：

- 凤凰单丛 / 乌龙茶做青为什么重要；
- 现有生产方式有哪些痛点；
- 行业正在向什么方向发展；
- 为什么现在适合做这件事。

建议证据：

- 权威产业数据；
- 茶厂 / 师傅访谈；
- 论文；
- 现有设备 / 产品；
- 政策或产业数字化趋势。

所有市场规模、产业规模、增速等数据必须注明来源。

## 2.2 项目概述

写清楚：

- 项目名称；
- 核心定位；
- 产品形态；
- 技术框架；
- 目标客户；
- 主要应用场景。

核心技术链：

> 多模态感知 → 状态估计 → 工艺决策 → 执行 → 品质反馈。

## 2.3 发展历程

建议用时间轴写真实节点：

- 选题与调研；
- 文献 / 专利查新；
- MVP 设计；
- 硬件开发；
- 数据采集；
- 算法验证；
- 样机集成；
- 茶厂 / 合作社试验；
- 专利 / 论文 / 软著等。

尚未发生的节点放到“未来展望”，不要提前写成已完成。

## 2.4 项目应用

官方要求重点呈现应用场景、小试 / 中试、行业认可、落地进展和应用效果。

正式版本优先准备：

- 真实茶厂试用；
- 合作社试验；
- 小批量做青实验；
- 连续运行记录；
- 师傅 / 企业反馈；
- 应用证明；
- 合作意向；
- A/B/C 三组对照结果。

当前无相关成果时写“正在推进 / 待验证”，不得用素材图替代真实应用。

## 2.5 社会价值

建议从具体价值出发：

- 传统制茶经验数字化沉淀；
- 降低批次波动；
- 为中小茶企提供低成本数字化改造路径；
- 辅助人才培养与经验传承；
- 促进广东特色茶产业数字化升级。

避免堆砌“乡村振兴”“赋能产业”等空话，尽量给出可量化指标或真实案例。

# 三、项目优势

这是商业计划书重点章节之一。

## 3.1 产品 / 服务

建议按模块描述：

### 产品 A：多模态感知终端

- MOS 电子鼻；
- RGB 相机；
- 称重；
- 叶温；
- 环境温湿度。

### 产品 B：做青控制 / 改造模块

- 电机调速；
- 滚筒控制；
- 采样气路；
- 半自动 / 自适应控制。

### 产品 C：软件与数据平台

- 实时数据；
- 状态估计；
- 控制建议；
- 加工档案；
- 批次对比。

当前尚未完成的模块标注研发状态。

## 3.2 技术原理

用一张系统架构图说明：

> 传感 → 特征处理 → 状态估计 → 决策 → 执行 → 品质反馈。

技术细节重点解释：

- 为什么使用多模态；
- 为什么 MOS 电子鼻需要气路与漂移补偿；
- 如何定义“做青状态”；
- 如何把状态转换成工艺决策；
- 如何防止错误控制。

## 3.3 创新点

建议保持三项：

1. 多模态做青状态表征；
2. 跨批次 / 跨环境自校准；
3. 品质导向的状态驱动控制。

每项创新必须对应：

> 已有方案 → 具体缺口 → 本项目方法 → 验证指标。

禁止在正式查新前使用“国内首创”“行业首次”等表述。

## 3.4 技术可行性

可用证据：

- 文献；
- 已有自动做青设备；
- 电子鼻在线监测研究；
- 团队实物；
- 电路 / PCB；
- 数据；
- 对照实验；
- 专利 / 论文 / 软件著作权。

正式申报时，论文、专利等关键支撑材料需与申报系统上传材料一致。

## 3.5 与竞品 / 现有研究对比

建议形成能力矩阵，不只比较“有没有 AI”。

维度示例：

- 自动执行；
- VOC 在线监测；
- 视觉 / 失水融合；
- 跨批次校准；
- 状态驱动决策；
- 品质闭环验证；
- 改造成本；
- 维护复杂度。

# 四、市场分析

这是商业计划书重点章节之一。

## 4.1 行业分析

回答：

- 凤凰单丛 / 乌龙茶产业链结构；
- 加工端数字化程度；
- 自动化设备发展方向；
- 中小茶企面临的现实约束。

所有行业规模和趋势数据必须注明来源。

## 4.2 市场分析

不要把全国茶叶总产值直接当作本项目市场规模。

应逐步缩小到：

> 茶产业 → 乌龙茶加工 → 做青设备 / 数字化改造 → 可触达目标客户。

推荐同时估算：

- 潜在客户数量；
- 单客户可接受设备预算；
- 更新 / 改造周期；
- 售后与维护需求。

以上均需调研验证。

## 4.3 客户需求

至少开展三类访谈：

- 制茶师傅；
- 茶企 / 合作社负责人；
- 茶叶科研 / 教学人员。

记录：

- 最痛的问题；
- 现有解决方式；
- 愿不愿意使用；
- 最担心什么；
- 能接受的成本；
- 是否愿意试用。

## 4.4 竞品分析

竞品包括：

- 自动摇青 / 做青设备；
- 传统固定程序控制设备；
- 茶叶电子鼻监测系统；
- 通用机器视觉 / 环境监测方案。

正式版本须列出具体企业、产品、论文或专利，不能只写“国内竞品”“国外竞品”。

# 五、商业模式

这是商业计划书重点章节之一。

当前建议作为**待验证商业假设**：

## 5.1 盈利模式

可能包括：

1. 感知终端 / 控制设备销售；
2. 现有做青设备数字化改造；
3. 软件与数据分析服务；
4. 售后维护与校准；
5. 面向科研 / 教学的实验平台。

正式版本必须通过客户调研验证“谁付费、为什么付费、付多少”。

## 5.2 运营模式

推荐描述完整交付流程：

需求调研 → 现场评估 → 设备安装 / 改造 → 校准 → 试运行 → 培训 → 数据迭代 → 售后维护。

## 5.3 营销策略

早期更适合：

- 茶企 / 合作社试点；
- 学校 / 科研单位合作；
- 行业协会 / 茶叶研究机构；
- 示范客户案例；
- 展会 / 行业活动。

不要在没有执行基础时写大规模渠道布局。

# 六、团队介绍

## 6.1 团队组成

每位成员按“专业背景 + 核心能力 + 项目职责 + 已完成工作”写。

能力建议覆盖：

- 电子硬件 / 嵌入式；
- 信号处理 / 算法；
- 自动化 / 控制；
- 茶学 / 食品化学；
- 产业调研 / 产品与商务。

## 6.2 顾问与指导

说明：

- 指导教师专业方向；
- 茶学 / 食品检测资源；
- 茶企 / 合作社顾问；
- 对项目具体提供什么支撑。

避免只列老师职称而没有项目关联。

---

# 七、财务分析

这是商业计划书重点章节之一。

当前项目尚处研发阶段时，财务章节可以先从“成本可行性”做起，不必强行编造三年营收。

## 7.1 原型成本

建立真实 BOM：

- 传感器；
- PCB；
- 气泵 / 阀；
- 相机；
- 称重；
- 电机 / 控制器；
- 结构件；
- 工控 / 边缘计算；
- 装配与测试。

## 7.2 产品成本

区分：

- 固定成本；
- 变动成本；
- 人力；
- 维护；
- 销售 / 市场；
- 软件服务成本。

## 7.3 财务预测

未来一至三年可预测：

- 销量；
- 营收；
- 成本；
- 毛利；
- 净利；
- 现金流；
- 回收期。

但每个数字都必须有假设依据和计算过程。

当前缺少真实售价 / 客户 / 订单数据时统一标“待调研验证”。

# 八、融资需求

当前尚未成立公司、无融资计划时，应如实写明。

若后续形成融资需求，再补充：

- 融资金额；
- 股权出让比例；
- 估值依据；
- 资金用途；
- 股权结构；
- 退出机制。

资金用途建议细分：

- 研发；
- 样机 / 小批量生产；
- 检测与认证；
- 市场试点；
- 运营；
- 流动资金。

不得为了“像商业计划书”而虚构融资历史或投资方。

# 九、风险控制

## 9.1 技术风险

- MOS 漂移；
- 高湿环境干扰；
- 跨茶季泛化不足；
- 数据量不足；
- 控制策略误判。

对应：校准、补偿、置信度机制、人工确认、安全边界。

## 9.2 市场风险

- 茶企购买意愿不足；
- 师傅对设备信任度不足；
- 改造影响生产流程；
- 维护成本过高。

对应：先做决策辅助、低风险试点、模块化改造、建立示范用户。

## 9.3 财务与供应链风险

- 传感器批次差异；
- 器件涨价 / 停产；
- 现金流不足；
- 小批量成本高。

对应：替代器件验证、模块化设计、阶段性投入。

# 十、未来展望

## 10.1 未来一年

推荐真实可执行目标：

- 完成 MVP；
- 完成多批次数据采集；
- 完成 A/B/C 对照实验；
- 完成半自动控制原型；
- 完成至少一轮真实茶厂 / 合作社试验；
- 形成专利 / 论文 / 软件成果的申报基础。

## 10.2 未来三年

建议方向：

- 多茶季验证；
- 多品种迁移；
- 模块化产品；
- 现有做青设备改造；
- 茶厂应用案例积累；
- 数据库与数字工艺服务。

目标应随着真实研发和市场反馈滚动更新。

# 十一、官方格式要求

正式提交前按官方模板排版：

- 正文总字数：12000 字以内；
- 文件大小：10 MB 以内；
- 正文：宋体，四号，全文不加粗，西文 Times New Roman；
- 一级标题：黑体，三号；
- 二级标题：楷体，三号；
- 三级标题：宋体，四号；
- 页边距：上 / 下 3.5 cm，左 / 右 2.8 cm；
- 页眉：1.5 cm；
- 页脚：1 cm；
- 行距：固定值 28 磅；
- 段前 / 段后：0；
- 两端对齐；
- 页码：页面底端居中，小四 Times New Roman；
- 图名位于图下，按章节编号；
- 表名位于表上，按章节编号；
- 图 / 表尽量不跨页；
- 论文、专利、合同、媒体报道等支撑材料应按申报要求另行上传，不在正文中堆叠。

---

# 十二、真实性与证据检查

正式提交前逐项检查：

- [ ] 所有市场数据有来源；
- [ ] 所有技术指标来自真实实验；
- [ ] 所有“应用”确有真实场景；
- [ ] 所有客户 / 企业名称已获允许或来源明确；
- [ ] 所有论文 / 专利作者与项目关系真实；
- [ ] 所有财务预测有假设和计算过程；
- [ ] 未把计划写成成果；
- [ ] 未把行业已有技术写成首创；
- [ ] 商业计划书、PPT、申报书中的数字一致。

当前项目最优先补的不是“写满商业计划书”，而是获得：

> **真实样机 + 真实实验 + 真实茶厂反馈 + 真实成本。**

有了这四类证据，商业计划书才会从模板材料变成可信的创业项目材料。
