# 青韵智控研究报告

## 0. 报告定位

项目名称：**青韵智控——凤凰单丛做青多模态感知与自适应控制系统**。

本项目面向“挑战杯”科技发明制作类作品培育。报告不以“堆算法、堆传感器”为目标，而以评审最关心的四条证据链组织内容：

1. **真实问题是否存在**；
2. **现有技术为什么还不够**；
3. **学生团队具体做出了什么作品**；
4. **实验和应用证据是否能证明作品有效且有转化价值**。

当前阶段属于“开题—原型研发”阶段。凡尚未获得真实实验数据、样机照片、茶厂应用证明的内容，均按“计划验证/目标指标”表述，不提前写成既有成果。

---

# 1. 一句话项目定义

凤凰单丛做青已经可以机械化执行，但“什么时候摇、摇多久、摇多重、静置多久”仍高度依赖制茶经验。

本项目尝试将老师傅对香气、色泽、失水和叶温等信息的综合判断转化为可连续测量的数据，并让这些**实时鲜叶状态**参与做青工艺决策。

核心闭环：

> **多模态感知 → 做青状态估计 → 工艺决策 → 执行 → 品质反馈**

本项目不是再做一台自动摇青机，而是研究：

> **如何把自动执行升级为状态驱动的自适应做青。**

# 2. 真实问题与需求验证

## 2.1 需要解决的真实矛盾

做青是凤凰单丛形成香气与品质的重要环节。实际工艺中，制茶师傅通常需要综合：

- 闻香气变化；
- 看叶缘红变和色泽；
- 触摸叶片柔软度与失水状态；
- 结合天气、温湿度和前几轮摇青情况；

再决定下一次摇青的时机、强度与静置时间。

现有机械设备可以按照预设程序运行，但天然鲜叶存在批次差异：

- 茶季不同；
- 天气不同；
- 鲜叶嫩度不同；
- 初始含水率不同；
- 不同香型/品种存在差异。

因此固定程序未必适合所有原料状态。

## 2.2 挑战杯阶段必须补齐的需求证据

本项目后续必须取得至少三类一手证据：

### A. 制茶师傅访谈

记录：

- 师傅判断“该摇了”的具体依据；
- 最容易判断失误的场景；
- 雨水青、不同茶季等情况下是否需要调整工艺；
- 对辅助判断系统最关心的指标。

### B. 茶企/合作社需求

记录：

- 当前做青设备类型；
- 人工参与频率；
- 批次稳定性痛点；
- 是否愿意接受外挂式感知模块/改造方案；
- 可接受成本和维护方式。

### C. 真实工艺影像

必须积累：

- 鲜叶；
- 晒青/凉青；
- 做青；
- 老师傅判断过程；
- 现有设备；
- 真实实验场景。

这些内容既是需求证据，也是后续挑战杯 PPT 最重要的视觉素材。

# 3. 已有技术边界：哪些不能算我们的创新

现有研究和设备已经能够做到：

1. 自动摇青和固定程序控制；
2. 温湿度等环境参数监测；
3. 利用电子鼻/MOS 气敏阵列识别乌龙茶加工阶段或追踪 VOC 变化；
4. 利用机器视觉提取色泽与形态信息；
5. 使用 GC-MS 等实验室方法分析关键挥发性物质。

因此以下内容**不能单独包装成创新点**：

- “自动摇青机”；
- “温湿度自动控制”；
- “电子鼻识别做青阶段”；
- “RGB 识别茶叶颜色”；
- “用了 AI”；
- “分类准确率比某篇论文高一点”。

真正值得推进的是下面三个技术增量。

# 4. 三个核心技术问题

## 4.1 多模态鲜叶状态表征

单一电子鼻主要反映 VOC 变化，但可能出现“气味相近、失水状态不同”的情况。因此第一项核心问题是：

> **如何融合香气、视觉、失水、叶温和环境信息，形成可解释的做青状态表征？**

输入候选包括：

- VOC 指纹；
- 叶缘红变与色泽；
- 失水率/失水速率；
- 叶温；
- 环境温湿度；
- 距上一次摇青时间；
- 历史摇青强度与持续时间。

输出不只做“第几摇分类”，而应尽量形成：

- 当前做青阶段；
- 香气发展水平；
- 失水状态；
- 红变程度；
- 综合状态指数；
- 模型置信度。

## 4.2 跨批次稳定与自校准

真实生产最大的难点之一不是单批数据集准确率，而是跨茶季、跨天气、跨批次稳定性。

同时 MOS 传感器存在：

- 温湿度干扰；
- 基线漂移；
- 老化；
- 器件批次差异；
- 吸附残留与恢复时间。

因此系统需要验证：

- 动态基线校正；
- 温湿度补偿；
- 周期参考校准；
- 跨批次归一化；
- 必要时的迁移学习/域适配。

## 4.3 从状态识别进入工艺控制

第三项也是最核心的问题：

> **识别出状态后，能不能真正指导下一步工艺？**

需要输出：

- 是否进入下一次摇青；
- 摇青转速/强度；
- 摇青持续时间；
- 下一次静置时间；
- 是否接近做青终点并进入杀青。

项目最终价值不由“阶段识别准确率”决定，而由：

> **是否能降低成茶批次间品质波动，并减少不必要的人工判断。**

# 6. 在线可测指标与实验室 Ground Truth

## 6.1 低成本在线指标

### VOC 气味指纹

使用 MOS 气敏阵列。项目必须避免直接声称“低成本 MOS 精确测出某一种香气分子浓度”。更合理的定义是：

> **综合色气体响应指纹及其随做青过程的动态变化。**

### RGB 视觉

候选特征：

- HSV/Lab 色彩；
- 叶缘红变比例；
- 纹理；
- 卷曲程度；
- 覆盖率。

### 失水状态

在线称重获得：

- 当前质量；
- 相对初始质量；
- 失水率；
- 失水速率。

### 叶温与热湿环境

用于：

- 描述鲜叶状态；
- 解释失水过程；
- 补偿电子鼻环境干扰。

## 6.2 实验室真值

用于证明在线信号是否具有品质意义：

- HS-SPME-GC-MS 关键 VOC；
- 标准含水率测定；
- 茶多酚；
- 游离氨基酸；
- 咖啡碱；
- 可溶性糖；
- 专家感官审评。

原则：

> 在线传感器负责“连续、低成本”，实验室检测负责“高可信标定与终点验证”。

# 7. 技术路线

## 7.1 鲜叶初始状态建档

每批记录：

- 品种/香型；
- 采摘日期；
- 天气；
- 初始质量；
- 初始视觉状态；
- 初始 VOC 基线；
- 初始叶温；
- 环境温湿度。

## 7.2 多模态同步采集

所有通道使用统一时间戳：

> 气味 + 视觉 + 质量 + 叶温 + 环境 + 工艺动作

必须能够完整重建一批茶的做青历史。

## 7.3 特征处理

电子鼻：

- 基线；
- 峰值；
- 响应斜率；
- 积分面积；
- 恢复时间；
- PCA/PLS 等降维特征。

视觉：

- 色彩；
- 红变；
- 纹理；
- 形态。

过程变量：

- 失水率；
- 失水速率；
- 温差；
- 距上次摇青时间；
- 累计机械刺激量。

## 7.4 状态估计

第一阶段优先使用可解释、适合小样本的方法：

- PCA/PLS；
- LDA；
- Random Forest；
- XGBoost；
- 轻量 MLP；
- 简单时序模型。

数据量充足后再讨论复杂深度模型。

## 7.5 工艺决策

第一代建议采用：

> **状态估计 + 规则约束 + 人工确认**

例如：

- 失水不足、青气型响应仍高 → 继续静置；
- 目标香气响应上升且失水进入区间 → 建议下一次摇青；
- 综合状态进入目标窗口 → 建议进入杀青。

后续才逐步探索：

- MPC；
- 数据驱动控制；
- 时序模型辅助参数优化；
- 强化学习仅作为长期研究方向，不作为第一版卖点。

# 8. 电子鼻工程实现与验证

## 8.1 传感器阵列

第一阶段建议 6–10 路，不追求“传感器越多越先进”。筛选依据：

- 响应差异；
- 重复性；
- 恢复速度；
- 温湿度敏感性；
- 成本；
- 供货稳定性。

候选可从 Figaro TGS、MQ、MEMS MOS 等系列中筛选，最终型号必须通过预实验决定。

## 8.2 气路

必须包含：

- 茶叶采样端；
- 过滤/防颗粒；
- 稳流；
- 气敏腔体；
- 气泵；
- 采样/清洗切换；
- 洁净空气或活性炭清洗通路。

## 8.3 必做工程实验

电子鼻可靠性必须单独形成实验章节：

1. 重复性实验；
2. 温湿度扰动实验；
3. 基线漂移实验；
4. 连续采样恢复实验；
5. 不同传感器批次一致性实验；
6. 跨批次茶样泛化实验。

这些实验的价值往往高于单纯把分类准确率再提高 1%。

# 9. 核心实验设计：建立完整证据链

## 9.1 三组对照

### A 组：老师傅传统做青

作为高质量人工基准。

### B 组：固定程序自动做青

代表已有自动化方式。

### C 组：状态驱动自适应做青

使用本项目系统。

三组尽量保证：

- 同品种；
- 同采摘标准；
- 同批鲜叶随机分组；
- 相同后续杀青、揉捻、烘焙条件。

## 9.2 数据划分

禁止将同一批茶不同时间点随机拆分到训练集和测试集。

正确做法：

> **按完整加工批次划分训练、验证和测试。**

正式阶段还应加入：

- 跨天气测试；
- 跨茶季测试；
- 条件允许时跨香型/品种测试。

## 9.3 评价指标

### 过程层

- 阶段识别准确率；
- 最佳摇青时机误差；
- 含水率/失水状态估计误差；
- 传感器重复性；
- 控制响应时间。

### 品质层

- 专家感官审评；
- 香气/滋味评分；
- GC-MS 关键 VOC；
- 茶多酚；
- 游离氨基酸等。

### 工程层

- 批次间品质波动；
- 人工干预次数；
- 单位能耗；
- 单批处理时间；
- 系统稳定运行时长；
- 原型成本。

## 9.4 最关键结果

挑战杯正式阶段最有说服力的结果不是：

> “模型准确率 97%。”

而应尽量形成：

> **与固定程序相比，自适应控制是否降低成茶批次波动；与老师傅相比，是否在可接受范围内复现优质工艺；同时是否减少部分重复人工判断。**

# 10. 三项拟申报核心创新及其验证方式

## 创新一：多模态做青状态表征

### 技术增量

融合 VOC、视觉、失水、叶温和环境信息，不再只输出加工阶段标签，而是建立可解释的鲜叶状态描述。

### 必须验证

- 单模态 vs 多模态；
- 不同组合消融实验；
- 跨批次性能。

---

## 创新二：跨批次自校准与漂移补偿

### 技术增量

针对天然鲜叶分布变化与 MOS 漂移问题，建立动态基线、环境补偿与批次校准机制。

### 必须验证

- 不补偿 vs 补偿；
- 同批次 vs 跨批次；
- 不同湿度/天气条件。

---

## 创新三：品质导向的状态驱动控制

### 技术增量

让在线状态从“被监测的结果”进入“工艺决策回路”。

### 必须验证

- 人工做青；
- 固定程序；
- 状态驱动控制；

最终以成茶品质和批次稳定性作为主要结果，而不仅是控制参数本身。

# 14. 风险与 Plan B

## 风险 1：电子鼻稳定性不足

Plan B：降低其权重，采用视觉 + 失水 + 环境作为稳定基础模态，电子鼻作为增强信息；同时把“电子鼻漂移补偿”本身作为工程研究对象。

## 风险 2：GC-MS 资源有限

Plan B：仅在关键做青节点和最终成茶进行检测，减少样本量；优先用于验证趋势而不是高频在线检测。

## 风险 3：真实茶季样本不足

Plan B：先固定单一香型/单一茶季完成闭环，明确项目边界，不虚构“全品种通用”。

## 风险 4：自动闭环控制风险高

Plan B：正式作品先做到“AI 推荐 + 人工确认”，只对安全参数实行自动控制。比赛中可将“辅助决策”作为已完成作品，将“完全闭环”作为下一阶段研发。

## 风险 5：没有茶学导师或品质评价支持

Plan B：暂缓自动控制路线，先做可靠的“做青数字化监测与工艺记录系统”。在缺少可靠 Ground Truth 前，不应强行训练所谓“最佳做青模型”。

# 15. 挑战杯证据成熟度矩阵

正式参赛前，建议用下表持续检查项目成熟度。

# 16. 当前最小可行原型 MVP

第一阶段只要求做到四件事：

1. **可靠采集**：同步记录 VOC、视觉、失水、叶温与环境；
2. **完整建档**：能重建一整批茶的做青全过程；
3. **状态推荐**：输出当前状态和下一步建议，由人工确认；
4. **真实验证**：跟随老师傅做一批完整实验，并把传感曲线与人工判断对齐。

只要这四件事做扎实，项目就从“概念”进入了真正可打磨的挑战杯作品阶段。

# 17. 当前阶段最优先的五件事

1. 找到懂凤凰单丛做青的导师/师傅/茶企合作对象；
2. 确认真实茶季采样机会；
3. 搭建第一版电子鼻 + 温湿度 + 称重同步采集系统；
4. 制定第一版完整实验 SOP 与批次编号规则；
5. 开始建立“评委问题—证据缺口—研发动作”台账。

项目后续所有 PPT、论文、专利与比赛材料，都应从真实实验和实物证据中长出来，而不是反过来为了 PPT 拼技术。
